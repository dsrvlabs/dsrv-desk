# 복구 코드 로그인 → 2차 인증 강제 재설정 기획

작성 2026-09-17 · 결정 근거 = 2026-09-17 사용자 지시(복구 코드로 로그인하면 대시보드로 보내지 않고 2차 인증 재설정으로 직행, 설정 완료 후 대시보드) · 재설정 범위 = 2FA 재등록만(비밀번호 제외)

## 1. 현행의 문제

| # | 문제 | 현행 스펙 위치 |
|---|---|---|
| 1 | 복구 코드로 로그인해도 인증 앱을 다시 등록할 **강제 수단이 없다**. DASH-01 권고 배너 1개뿐이고 닫기만 없을 뿐 무시할 수 있다 | AUTH-03 항목 1 · DASH-01 항목 2 |
| 2 | 복구 코드는 1개·1회용이고 **인증 성공 즉시 폐기**된다. 인증 앱은 이미 분실 상태이므로, 그 세션이 끊기는 순간 로그인 수단이 0개가 되는 데드락이 생긴다 | AUTH-03 항목 1 · 상세 1 |
| 3 | 재설정 경로(DASH-03)가 ONB-01부터 재수행이라 **비밀번호까지 강제로 교체**된다. 앱 분실은 비밀번호 분실이 아니다 | DASH-03 상세 1 |
| 4 | 재설정 완료 시 전체 세션 로그아웃 → AUTH-01 재로그인이라 **작업 흐름이 끊긴다** | DASH-03 항목 2 |
| 5 | Figma 2차 시안의 "확인 후 2FA가 초기화됩니다" 대안이 `[확인필요]`로 미결 상태였다 | AUTH-03 상세 2 |

## 2. 결정

1. AUTH-03 복구 코드 인증 성공 → **세션을 만들되 계정에 `재설정 대기` 플래그를 세우고 DASH-03 강제 모드로 보낸다.** 대시보드로 가지 않는다.
2. `재설정 대기` 상태에서는 DASH-03 외 모든 콘솔 화면 접근을 막는다. 허용 동작은 로그아웃뿐이다.
3. 강제 모드의 재설정 범위는 **2FA 재등록 + 새 복구 코드 발급**이다. 비밀번호는 건드리지 않는다(AUTH-01 1단계에서 이미 검증됨).
4. **복구 코드 폐기 시점을 '인증 성공 즉시'에서 '재등록 완료 시'로 옮긴다.** 재설정 대기 중에는 같은 코드로 다시 로그인할 수 있어 세션 만료 데드락이 사라진다. DASH-03이 이미 쓰던 "기존 OTP·복구 코드는 재등록 완료 시 무효화" 원칙과 같다.
5. 재등록을 마치면 그 컨텍스트에 세션을 만들고 **DASH-01로 보낸다**(계정당 1세션이므로 기존 세션은 종료).
6. **메일은 템플릿 1종을 공유하고 문안 세트를 3종으로 나눈다.** 초대 메일 레이아웃을 재사용하되 제목·본문 제목행·안내 박스·버튼 라벨을 용도별로 바꾸고, 1조직 1계정 고지는 재설정에서 뺀다.

## 3. 목표 흐름

```
AUTH-01 비밀번호 성공
  ↓
AUTH-02 2차 인증 → [복구 코드로 인증]
  ↓
AUTH-03 복구 코드 입력 성공
  ↓  세션 생성 + 계정 `재설정 대기` ON · 복구 코드는 아직 유효
DASH-03 강제 모드 (이전으로 없음 · 다른 화면 접근 차단)
  ↓  [재설정 메일 발송]
📧 재설정 메일 · 2fa 문안 ("인증 앱을 다시 등록해 주세요" / 버튼 [인증 앱 재등록])
  ↓  링크
ONB-02 2FA 재등록 (2차 인증 재설정 1/2)
  ↓
ONB-03 새 복구 코드 (2차 인증 재설정 2/2)
  ↓  [확인] → 이전 복구 코드 폐기 · `재설정 대기` OFF · 세션 생성
DASH-01 대시보드 (재설정 완료 안내 배너)
```

## 4. 신설 상태값

| 값 | 설정 시점 | 해제 시점 | 효과 |
|---|---|---|---|
| `재설정 대기`(가입자 계정 플래그) | AUTH-03 복구 코드 인증 성공 | ONB-03 [확인] (재설정 2fa 모드) 완료 | DASH-03 강제 모드 외 전 화면 접근 차단 · 재로그인해도 같은 상태로 복귀 |

- 계정 상태 칩(ADM-04 · 초대 발송됨/활성/잠금/해지)과는 **별개 축**이다. 계정 상태는 '활성'을 유지한다.
- 어드민 화면에 노출하지 않는다(처리함 아이템 생성 없음). 감사로그에만 설정·해제를 남긴다.

## 7. 화면별 변경 명세

### AUTH-03 복구 코드로 인증
- 항목 1 **연동**: 성공 시 코드를 즉시 폐기하지 않고 계정에 `재설정 대기`를 세운 뒤 세션을 만들고 **DASH-03 강제 모드**로 보낸다. 코드 폐기는 ONB-03 [확인] 시점이다.
- 항목 2 [인증] 이동 대상: `DASH-01` → `DASH-03(강제 모드)`.
- 상세 2 전면 개정 — 기존 `[확인필요]`(2차 시안 '2FA 초기화' 대안) 해소. 시안의 "다시 로그인하고 2FA를 설정" 대신 **세션을 유지한 채 재설정을 강제**하는 방식으로 확정한다.

### DASH-03 2차 인증 재설정
- **진입 2종으로 분기**
  - 자발(DASH-01 계정·보안 카드) = 현행. 비밀번호 + 2FA. '‹ 이전으로' 노출. 완료 시 전체 로그아웃 → AUTH-01.
  - 강제(AUTH-03 성공 직후) = 신규. 2FA만. '‹ 이전으로' **미노출**. 완료 시 세션 생성 → DASH-01.
- 강제 모드 안내문: "인증 앱을 다시 등록해야 서비스를 이용할 수 있습니다. 본인 이메일 `{담당자 이메일}`로 재설정 링크가 발송되며, 링크에서 인증 앱 재등록과 새 복구 코드 발급을 진행합니다." + "※ 재등록이 끝나면 새 복구 코드가 발급되고 이전 코드는 폐기됩니다. 재등록 완료 전까지 현재 복구 코드로 다시 로그인할 수 있습니다."
- 강제 모드에서는 콘솔 다른 화면으로 나갈 동선이 없다(GNB 없음은 현행과 동일 · '이전으로'만 제거).

### ONB-02 2FA 앱 연결
- 진입 3종: ① ONB-01 [다음] ② 초대 링크 재개 ③ **재설정 링크**(문안 `full`·`2fa` 공통).
- 스텝 표기 분기: `계정 활성화 2/3` / `인증 수단 재설정 2/3`(full) / `2차 인증 재설정 1/2`(2fa).
- 검증 성공 시 새 복구 코드를 생성해 ONB-03으로 넘기는 동작은 모드 공통이다.

### ONB-03 복구 코드 저장
- 스텝 표기 분기: `계정 활성화 3/3` / `인증 수단 재설정 3/3` / `2차 인증 재설정 2/2`.
- [확인] 액션 3분기

| 모드 | 액션 | 다음 |
|---|---|---|
| 활성화(`invite`) | 계정 활성 · 토큰 소멸 | AUTH-01 |
| 재설정 `full` | 새 코드 발급 · 이전 코드 폐기 · 전체 세션 로그아웃 | AUTH-01 |
| 재설정 `2fa` | 새 코드 발급 · 이전 코드 폐기 · `재설정 대기` 해제 · 이 컨텍스트에 세션 생성(기존 세션 종료) | **DASH-01** |

- 다이얼로그 문구는 3모드 공통을 유지한다.

### DASH-01 홈·대시보드
- 항목 2 배너를 **'2차 인증 재설정 권고' → '2차 인증 재설정 완료 안내'로 교체**한다. 권고 배너는 강제 이동이 대체하므로 존재 이유가 사라진다. 항목 번호는 유지한다(notation이 DASH-01 항목 5를 참조).
- 문구: "인증 앱이 다시 등록되었습니다. 새 복구 코드를 안전한 곳에 보관해 주세요."
- 노출: 강제 재설정 완료로 진입한 직후 1회. 새로고침·재진입 시 사라진다.

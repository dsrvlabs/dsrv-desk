## 넣기 전에 확인할 것

1. **B4 정산 내역(완료) 수치**: EXC-04 상세내용에 받은 자산이 두 값으로 적혀 있다.
   상태 변형 표는 「완료 = 899.73 USDT」, 항목 설명은 「가스비를 차감한 실수령액(예 893.77)」.
   이 파일은 **899.73**으로 만들었다. 스토리보드 내부 불일치이므로 확정 후 재생성한다.
2. **B2 확정 견적 화면**: 계획서 Ⅱ.3.라·아는 견적 화면에 기준가와 스프레드를 구분 표시한다고 썼다.
   화면에는 스프레드는 별도 항목으로 있으나 기준가 절대값은 없다. 기준가를 낼지 결정이 필요하다.
3. **C2 신청 화면**: 계획서 Ⅱ.4.마는 시세 참고자료를 양 당사자에게 동일 제공한다고 썼다.
   현 화면은 게시 화면(C1)에만 현 시세와 편차가 있고 신청 화면에는 없다.
4. 목업에서 스토리보드 전용 주석(▼ 표시 · 핀 번호 · 조건부 상태 변형)은 자동으로 제거했다.
   계획서에 넣기 전에 `[확인필요]`·`{정책값}` 문자열이 남아 있지 않은지 눈으로 한 번 더 본다.

## 계획서 본문 수정과 함께 반영해야 하는 것

이 그림들은 2026-09-11 결정(09 §0 (28))을 반영한 상태다. 계획서 본문도 같이 고쳐야 한다.

- 취급 자산에서 BTC 제외(ETH·USDT·USDC 3종 · Ethereum 단일)
- 협의 채널 서술 삭제(자유 메시지 채널·역제안 기능 없음)
- 괴리율 3단 통제 → 2단(확정 시점 확정 보류는 미구현)
- 게시 정보를 수량 범위에서 확정값으로
- 마목 당사자 용어를 매도인·매수인에서 게시자·신청자로
- 기준가 소스 코빗 → 빗썸(업비트·빗썸·바이낸스 3사 단순 산술평균)

## 만드는 법

작업 파일은 `drafts/storyboard/_export/`에 있다(버전 관리 대상 아님, 필요할 때 재생성).

- 서비스 흐름도: `overview.html`의 SVG 2개를 그대로 뽑아 폰트 대체 스택만 붙였다.
- 화면 목업: 화면 html에서 `.frame` 요소만 잘라 `screen.css`와 함께 단독 페이지로 만들고,
  ▼ 주석과 그 아래 조건부 요소를 스크립트로 지운 뒤 Windows Chrome headless로 2배 해상도 캡처했다.
- 신규 3종: `_diag.css`를 공유하는 HTML 페이지로 그리고 같은 방식으로 캡처했다.
- 캡처 명령: `chrome.exe --headless=new --force-device-scale-factor=2 --window-size=W,H --screenshot`
  높이는 페이지가 `document.title`에 실제 높이를 넣게 해서 1차 `--dump-dom`으로 읽고 2차에 적용한다.

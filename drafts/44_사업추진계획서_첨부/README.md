## 예시 자산 쌍 (2026-09-15 개정)

**이 폴더의 그림·목업은 전부 USDC(고객이 보냄) ↔ ETH 한 쌍만 쓴다**(사용자 지시).
종전에는 나목이 USDC→USDT, 마목이 USDT↔USDC였다.

| | 나목 교환 (A1 · B1~B4) | 마목 중개 (A2 · C0~C4) |
|---|---|---|
| 고객 A사 | 900 USDC 보냄 → ETH 받음 | 신청자 · 955.20 USDC 보냄 → 0.3 ETH 받음 |
| 상대 | DSRV 교환 재고(콜드) | 게시자 B사 · 0.3 ETH 보냄 → 955.20 USDC 받음 |
| 비율 | 참고 3,184.00 → 확정 3,187.18 USDC/ETH | 3,184.00 USDC/ETH (당사자 협의) |
| 받는 수량 | 참고 0.2826 ETH → 확정 0.2823 ETH | 각 0.3 ETH / 955.20 USDC |
| 수수료 | 없음(스프레드 0.10%에 내재) | 신청자 9.55 USDC · 게시자 0.0030 ETH (각자 1%) |

산출 근거와 가정:

- 기준가 **3,184.00 USDC/ETH**는 스토리보드가 이미 쓰던 값이다(brk-01·brk-02·exc-01 ETH 페어 예시).
  ETH 페어 비율은 방향과 무관하게 「{스테이블}/ETH」 2자리로 적는다.
- 확정 비율 3,187.18 = 3,184.00 × (1 + 스프레드 0.10%), 2자리 절사. 받는 수량은 900 ÷ 3,187.18 = 0.2823 ETH(4자리 절사).
  ⚠️ 별표 1 P3은 **ETH 페어 스프레드 요율을 아직 미정**으로 두고 있다. 0.10%는 스테이블 페어 값을 그대로 쓴 **가정**이다.
- C1 게시 화면의 현 시세 3,190.40 USDC/ETH는 편차 −0.20%(허용 ±2.0% 이내)를 보이려고 **역산한 값**이다.
- B1 교환 가능 풀 **ETH 560.0000**, C1 보유 **12.5000 ETH**는 화면을 채우기 위한 **예시값**이다.
- 한도 판정: 955.20 USDC ≈ 1,289,520원, 900 USDC ≈ 1,215,000원(1 USDC ≈ 1,350원 **가정**) — 건별 한도 1,500,000원 상당 이내.
- C0 게시판 목록 4행도 ETH↔USDC로 맞췄다(0.25/796.00 게재중 · 0.2/636.80 협의중 · 650/0.2041 내 게시 · 0.3/955.20 내 신청 = C2~C4의 그 건).

**스토리보드 원본은 바꾸지 않았다**(2026-09-15 사용자 결정). `drafts/storyboard/` 24화면 · `knowledge/09 §0` 예시 수량 ·
QA 시트 269 STEP은 USDC↔USDT를 그대로 쓴다. 따라서 **계획서 첨부의 수치와 스토리보드·QA의 수치는 서로 다르다**.
이 폴더의 `_export/*_frame.html`만 고쳐서 재캡처한 것이고, 원본으로 되돌리려면 `_export/.bak_20260915/`에 사본이 있다.

## 배치 규격 (2026-09-15 개정)

N1·N2·N2b·N3은 **A4 세로 문서의 본문 폭에 꽉 채워 넣는 것을 전제**로 다시 그렸다.
처음 판(가로 1180px, 본문 글자 10.5px)은 본문 폭에 맞추면 글자가 4pt대로 떨어져 읽히지 않았다.
해상도를 올려도 같은 문제가 남으므로, 단계를 가로로 늘어놓던 구조를 세로로 쌓고 글자를 키웠다.

| 파일 | 설계 크기(px) | 본문 폭 16cm 배치 시 | 최소 글자 |
|---|---|---|---|
| N1 | 814 × 1104 | 세로 21.7cm | 8.6pt |
| N2 | 814 × 1194 | 세로 23.5cm | 8.6pt |
| N2b | 814 × 331 | 세로 6.5cm | 8.6pt |
| N3 | 814 × 832 | 세로 16.4cm | 7.8pt |

- 넣을 때 **가로를 본문 폭(여백 제외 전체)에 맞추고 세로는 비율 고정**으로 둔다. 임의로 줄이면 글자가 다시 작아진다.
- N1과 N2는 한 페이지를 거의 채우므로 **앞뒤로 쪽 나눔**을 두고 단독 배치하는 편이 낫다.
- N2는 절차 6단계까지만 담고, 종결 경로 5종은 N2b로 분리했다. 한 장에 담으면 26.7cm가 되어 A4 한 페이지를 넘는다.
- 화면 목업(B·C)은 원래 세로로 긴 프레임이라 손대지 않았다. 본문 폭의 60~70%로 넣으면 글자 크기가 맞는다.
- 문서 여백이 기본값(2.54cm)이 아니면 위 세로 길이는 그만큼 달라진다.

## 넣기 전에 확인할 것

1. **B4 정산 내역(완료) 수치**: EXC-04 상세내용에 받은 자산이 두 값으로 적혀 있다.
   상태 변형 표는 「완료 = 확정 수량 그대로」, 항목 설명은 「가스비를 차감한 실수령액」이다.
   이 파일은 확정 수량 **0.2823 ETH**로 만들었다(가스비 차감 시 0.2823 − 0.0019 = 0.2804 ETH).
   스토리보드 내부 불일치이므로 확정 후 재생성한다.
2. **B2 확정 견적 화면**: 계획서 Ⅱ.3.라·아는 견적 화면에 기준가와 스프레드를 구분 표시한다고 썼다.
   화면에는 스프레드는 별도 항목으로 있으나 기준가 절대값은 없다. 기준가를 낼지 결정이 필요하다.
3. **C2 신청 화면**: 계획서 Ⅱ.4.마는 시세 참고자료를 양 당사자에게 동일 제공한다고 썼다.
   현 화면은 게시 화면(C1)에만 현 시세와 편차가 있고 신청 화면에는 없다.
4. 목업에서 스토리보드 전용 주석(▼ 표시 · 핀 번호 · 조건부 상태 변형)은 자동으로 제거했다.
   계획서에 넣기 전에 `[확인필요]`·`{정책값}` 문자열이 남아 있지 않은지 눈으로 한 번 더 본다.

## 만드는 법

작업 파일은 `drafts/storyboard/_export/`에 있다(버전 관리 대상 아님, 필요할 때 재생성).

- 서비스 흐름도: `overview.html`의 SVG 2개를 그대로 뽑아 폰트 대체 스택만 붙였다.
- 화면 목업: 화면 html에서 `.frame` 요소만 잘라 `screen.css`와 함께 단독 페이지로 만들고,
  ▼ 주석과 그 아래 조건부 요소를 스크립트로 지운 뒤 Windows Chrome headless로 2배 해상도 캡처했다.
- 신규 3종: `_diag.css`를 공유하는 HTML 페이지로 그리고 같은 방식으로 캡처했다.
- 캡처 명령: `chrome.exe --headless=new --hide-scrollbars --force-device-scale-factor=2 --window-size=W,H --screenshot`
  높이는 페이지가 `document.title`에 실제 높이를 넣게 해서 1차 `--dump-dom`으로 읽고 2차에 적용한다.
  **폭은 692**(`.frame` 640 + 테두리 2 + body padding 48). 좁게 잡으면 프레임 오른쪽이 잘린다.
  `--hide-scrollbars`를 빼면 스크롤바가 찍혀 폭이 어긋난다. A1·A2는 SVG 크기대로 580×210 / 580×220.

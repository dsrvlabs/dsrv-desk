- 배경 및 이슈

    - 웨이브릿지 등 기존 사업자는 **교환(딜러)까지 겸해** 자기자본·이해상충·규제 리스크가 큼.
    - 기관(법인)이 대량 가상자산을 **시장충격 없이·상대방 검증 하에·안전하게 정산**하며 교환할 중립 인프라가 부족.
    - DSRV는 이미 **커스터디(이전·보관관리)** 를 보유 → 그 위에 "중개+정산" 레이어만 얹으면 됨.
- 프로덕트 핵심 목표
    - **교환(나목) 확보 — 자사 상대방·비(非)가격형성**
        - DSRV가 교환 상대방이 되되(고객↔DSRV, ETH·USDC·USDT), **자체 오더북·자동 호가매칭·자동 체결·자체 시세산정 없이** 외부 지표 참조 **스프레드 고정 + 건별 수동집행 + 콜드 최소재고**로 운영 → '자동체결 거래소' 오인 리스크를 구조적으로 차단.
    - **교환 중개(마목) 확보 — 게시판형 순수 중개**
        - DSRV는 당사자·가격결정자가 되지 않고 **의향 게시판**으로 매도/매수 법인을 연결. **단순 게시판(VASP 제외)과 구분**하는 4요소(게재검증·KYC담보·정산연계·수수료)로 마목 해당성 확보.
    - **결제 안전성 (커스터디 수동 정산)**
        - 양측 자산이 DSRV 커스터디(100% 콜드)에 있어, 조건 확정·승인 후 **커스터디팀이 콜드월렛에서 에스크로 전용지갑 예치 2건 → 양건 예치 확인 → 인도 2건을 수동 집행**(2026-09-03(15) · 완결성은 운영절차로 담보). 별도 에스크로·핫월렛·자동 정산엔진 불필요.
    - **컴플라이언스 내재화**
        - CDD/EDD·BLF·KYT·STR·트래블룰 + 감독규정 §28(외부 VASP 참여 시) + 이상행위탐지(통정·자전 + 나목 재고세탁)를 정책 기반으로 운영.

### **🧪 사용자 공통 시나리오**

**🏢 시나리오 1 — 나목 교환 (고객 ↔ DSRV, USDC → ETH)**

1. 법인 A가 **교환 요청**(USDC 매도·ETH 매수, 수량·방향) — 잔고·한도 확인
2. DSRV가 **외부 지표 참조 스프레드 고정** 비율 제시(자체 시세산정·오더북 없음)
3. A 수락 → 정책·BLF·KYT **자동검증(1차 필터, 불량 시 수동검증)** → **고객사 1인 확인 + DSRV 단일 건별 승인**
4. **커스터디팀이 콜드월렛에서 수동 집행**: 교환재고에서 A로 ETH 전송 + A의 USDC 재고 편입 — 트래블룰 적용(2영업일급)
5. **거래보고서 발급**(스프레드 수익 구분회계), 기록 15년 보존

**🏢 시나리오 2 — 마목 교환 중개 (법인 A ↔ 법인 B, 게시판형)**

1. 매도 법인 A가 **의향 게시**(자산·수량·조건, **옵션: 가격 이탈 자동중지**) — DSRV가 보유·처분권 확인 후 게재
2. 매수 법인 B가 관심 → **당사자 간 협의**(DSRV 비참여·기록만, 자동 매칭·체결 없음) — 가격은 당사자 협의. **외부지표 임계 초과 시 RFQ 자동중지**(가드)
3. 수량·비율·일정 **조건 확정**(구속력 발생) → **승인**(정책·BLF·KYT 자동검증 1차·불량 시 수동검증 + **고객사 1인 + DSRV 단일**)
4. 각자 이전 지시 → **커스터디팀이 콜드월렛에서 양건 확인 후 수동 이전**(완결성은 운영절차로 담보) — 트래블룰 적용
5. **거래보고서 발급·수수료(1% 양측) 정산**, 기록 15년 보존

**🚫 예외 처리**

- 조건 확정 전 무산 → 자산 이동 없음, 수수료 없음
- **나목 재고 부족·스프레드 이탈 → 교환요청 보류**(집행 안 함)
- 제재(BLF)·고위험(KYT) 적출 또는 통정·자전·재고세탁 의심 → 시장감시 검토, 미소명 시 중단 → STR 연계

- **DSRV Platform Admin**: 전 ORG 관리·KYC 상태 설정·정책·지갑·**출금/체결 승인**·마스터 통제

### **🔐 보안 및 규제 대응**

- **VASP 「교환(나목) + 교환 중개(마목)」 변경신고** — 기존 이전·보관관리 유지
- **⚠️ 두 경계 방어(G0)**: 나목=자체 오더북·자동체결·자체 시세산정 없음 + 외부지표 스프레드 + 건별 수동집행 + 콜드 최소재고 → '자동체결 거래소' 아님 / 마목=게재검증·KYC담보·정산연계·수수료 4요소 → '단순 게시판' 아님
- **⚠️ 이해상충 방어(단일법인 마목·나목 겸업)**: ①**연속 양방향 호가 금지 → 단건 RFQ·블록딜** ②**API 자동체결 금지·수동 승인/타임딜레이** ③**차이니즈월: 나목 데스크의 게시판 비공개정보 격리** ④관계자 특혜·수수료 차등 금지 ⑤DSRV 연계 거래 시장감시 별도 플래그 ⑥'공식 LP·MM·보증' 라벨 금지 [근거 L6 §10]. ※별도법인(B) 분리안 미채택. "MiCA식 업권분리 = 국내 명문 근거 없음" [확인필요]
- **8-20 진입규제 대응**: 대주주 적격성·재무건전성(§7③5호)·사회적 신용·확대 결격(대표자·임원·대주주) 자기점검·증적 (수리 8-20 이후 대비)
- 감독규정 **§28** 준수(외부 VASP 참여 시), 트래블룰·미신고사업자 거래 차단
- MPC(키 전량 DSRV)·HSM·직무분리·다중승인 — **전량 콜드월렛(인터넷과 분리)·수동 운영, 나목 교환재고 포함** (이용자보호법 시행령 §11 콜드 요건 현행 충족)
- **배상책임보험(법 §8·시행령 §12)** 가입·한도 유지 / **예치금 §6 해당없음**(금전 미취급 — 신고서에 사유 명시)
- **입출금 차단 시 §11② 절차**: 이용자 사전통지 + 금융위 즉시보고(로그 보존)
- **자기발행 금지(§10⑤) 해당없음** — 취급자산 ETH(네이티브)·USDC·USDT는 DSRV 발행 아님
- **AML 거버넌스**: 보고책임자(자격·직위 §5)·직원알기제도·연 1회 교육·연 1회 독립감사
- **특권계정(DSRV Admin) 통제**: 전용 세션·행위 녹화·분기 권한 재검토(PAM)
- ISMS 통합 인증 유지 + 신규 시스템 **예비인증**(범위 변경)
- 거래기록 15년·AML 기록 5년·감사 추적·접근 로그 / 개인정보 최소 수집·파기주기 관리
- `[로펌게이트]` 나목 자사교환이 '자동체결 거래소'가 아님(수동집행·외부지표 스프레드·최소재고) + 마목 게시판이 '단순 게시판'이 아님(4요소) — G0 사전면담 확정

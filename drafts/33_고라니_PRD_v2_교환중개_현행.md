# 서비스 네이밍 — 왜 '고라니'인가

'고라니'는 한국의 가상자산 규제 환경을 빗댄 이름이다. 한국의 규제는 다른 나라에 비해 유독 심하다. 고라니 역시 전 세계에서 유독 한국에 대다수가 분포한다. 고라니는 어디서 나타날지 예측하기 어렵다. 한국의 규제도 꼭 그렇다. 예측 불가능하게 출몰하는 규제에 대응한다. 그래서, 고라니다.

# 1. 돌핀(Dolfin) 벤치마크 — 무엇을 따라가고 무엇을 뺐는가

돌핀(웨이브릿지)은 법인·고액자산가용 가상자산 관리 플랫폼이다. 참고 축과 우리 판단은 다음과 같다.

## 1-1. 거래 (Trading)
돌핀: 국가별 라이선스 LP 유동성 풀로 매매 체결, VASP가 상대방 리스크 차단.
우리 판단: 외부 LP 다중 연동·유동성 풀은 채택하지 않는다. 나목 교환은 DSRV 자사 콜드 최소재고로 상대방이 되되, 외부 지표 참조 스프레드·건별 수동집행으로 운영한다(7장).

## 1-2. 중개 (Brokerage)
돌핀: 블록딜 OTC, 브로커가 상대방 탐색·매매 계획 설계, 검증 회원 간 거래.
우리 판단: 마목은 게시판형으로 축소한다. DSRV는 당사자 협의에 개입하지 않고(비참여·기록만), 게재 검증·양측 KYC 담보·정산·수수료만 수행한다.

## 1-3. 통합 자산관리
증명서 발급(잔고증명·거래내역 증빙)과 통합 리포팅은 그대로 채택한다.

## 1-4. 공통 통제 (그대로 따라가는 부분)
KYC(고객확인) · Travel Rule · STR · ISMS · VASP. 돌핀의 거래·중개가 완전 자동 매칭 엔진이 아니라 사람 개입 + 수탁의 조합인 점은 우리 모델과 같다. 고라니 MVP도 사람이 개입하는 수동 데스크 + 얇은 소프트웨어 레이어로 시작한다.

# 2. 사용자 · 권한 모델

## 2-1. 가입 / 온보딩
초대 기반 ORG 가입. 공개 셀프 가입 없음. 법인 KYC는 수기(오프라인) 처리. 시스템은 KYC 승인 상태만 관리하며 승인 전까지 조회만 허용. ORG 단위로 자산·지갑·멤버 격리.

## 2-2. RBAC (역할 기반 권한)

| 역할 | 권한 |
|---|---|
| Platform Admin (DSRV) | 전 ORG 관리, 요청 단일 승인/반려, KYC 상태 설정, 마스터 통제 |
| ORG Owner | 멤버 초대, 역할 부여 |
| ORG Trader | 교환·중개 요청 생성 + **1인 확인**(실행은 DSRV 승인 후) |
| ORG Viewer | 대시보드·리포트 조회 전용 |

승인 구조는 v1의 ORG N-of-M을 폐지하고 고객사 1인 확인 + DSRV 단일 승인으로 간소화한다. 직무분리 완화의 보완통제는 3-C·9장 참조. 운영망/개발망 분리, 관리자-사용자 권한 분리는 ISMS 필수로 유지한다.

## A. 인증·계정 — [개발] (BE/FE)

## C. Policy Engine + 승인 — [개발] (BE) ★핵심
룰 기반 1차 자동검증: 출금/이전, 교환 체결, 중개 체결, 임계 금액, 화이트리스트, KYT/BLF 결과를 평가해 통과 / 보류 / 차단 결정. **자동검증은 1차 필터이며, 결과 불량(flag·고위험·부적합) 시 자동 거절이 아니라 사람이 수동검증 후 판단한다.**
승인 구조: 고객사 1인 확인 → DSRV 단일 승인(결재선/maker-checker 없음).
**직무분리 완화 보완통제** [근거 L13 2.2.2 직무분리 곤란 시 보완대책]: ① 사전등록 화이트리스트(신규주소 지연발효) ② 커스터디팀 콜드 건별 수동집행 = 물리적 2차 게이트(요청↔집행 조직 분리) ③ WORM 감사로그 15년 ④ 자동검증 후 수동검증.
※ 2단 가드: 고라니 Policy Engine = 비즈니스 룰·검증, 커스터디 정책 = 최종 서명 직전 가드레일.

## D. 승인 라인 (Approval) — [개발] (BE/FE)
승인 대기함(Inbox), 승인/반려 사유, 전체 이력 감사. N-of-M 순차 승인은 폐지, 단일 승인으로 운영.

## E. 수탁 지갑 (Custodial Wallet) — [사내 커스터디 연동] (BE) ★구조 핵심
**지갑은 100% 콜드·수동 운영. 운영 핫월렛과 자동 스윕은 두지 않는다.**
- 입금: ORG별 입금주소(HD/MPC 파생) 수령 → 사내 노드 감지 → KYT/BLF 점검 → 콜드 보관(수동 확인·반영).
- 출금·정산·교환 집행: 커스터디팀이 콜드월렛에서 건별 수동 서명·전송. 자동 정산엔진·핫월렛 없음.
- 나목 교환 최소재고도 콜드 편입(자사 소유).
- 고라니 개발 범위: 입금 감지·잔고 표시·화이트리스트·집행 요청 티켓·집행 상태 추적·잔액 정합성 대사. 콜드 보관·키관리·최종 서명은 커스터디.
- ✅ 선결 과제(커스터디 팀): (a) 주소 발급·서명 API, (b) 콜드 건별 수동집행 절차·SLA(마목 정산 영업일 내 3회 기준), (c) Ethereum 단일 체인(ETH 네이티브 + ERC-20 USDC·USDT), (d) ERC-20 출금 가스 충전 주체, (e) 집행 이중확인(4-eyes)·키운영자 이원화·DR 시 콜드 복구.

## F. KYC — [수기(오프라인) 전제] (시스템: 상태 플래그만)
법인 KYC 서류 제출·검토·승인은 시스템 밖 수기. 시스템은 ORG KYC 승인 상태(미승인/승인)만 관리하고 이 상태로 거래·출금 게이팅. 인앱 서류 업로드·심사 콘솔은 MVP 제외. 원본 5년 보관은 컴플라이언스 오프라인.

거래/출금 이벤트 → FDS 스코어 → Policy Engine 입력.

## H. OFAC / KYT (온체인 스크리닝) — [사내 확인 후] (BE 연동)

## I. 홈 대시보드 — [개발] (BE/FE)
관리 자산 총액, 자산 비중(ETH/USDC/USDT), 콜드 보관 현황, 나목 교환재고 잔량·한도, 최근 거래·승인 현황. 평가금액 산정 시세는 **외부 가격지표 참조**(가격 결정 아님).

## J. 교환하기 (나목) — [개발] (BE/FE) ★
법인 고객이 DSRV를 상대방으로 스테이블코인을 교환.
- 흐름: 교환 요청(방향·수량, 단건) → **외부 지표 참조 스프레드 고정 비율 제시** → 고객 수락 → 고객사 1인 + DSRV 단일 승인(자동검증 1차·불량 시 수동검증) → 커스터디 콜드 수동집행(재고 차감) → 보고.
- **거래소·MM 아님(통제)**: 자체 오더북·자동 호가매칭·자동 체결·자체 시세산정 없음. 연속 양방향 호가 금지(단건 RFQ·블록딜). API 자동체결 금지·수동 승인/타임딜레이. UI에 '공식 LP·마켓메이커·플랫폼 보증' 라벨 금지(평판 뱃지로 대체). [근거 L6 §2나목]
- 재고: 최소 한도·콜드 보유. 스프레드 이탈·재고 부족 시 요청 보류.

## K. 거래하기 (마목·게시판형) — [개발] (BE/FE) ★
법인 고객 간 교환 중개.
- 흐름: 의향 게시(자산·수량·조건, **가격 이탈 자동중지 옵션**) → 게시판 조회 → 당사자 협의(DSRV 비참여·기록만) → 조건 확정 → 고객사 1인 + DSRV 단일 승인 → 커스터디 콜드 수동 이전(양건 확인 후 순차) → 보고·수수료 1% 양측. (대상 시 Travel Rule)
- **단순 게시판 아님(마목 해당성 4요소)**: 게재 검증(보유·처분권) + 양측 KYC 담보 + 정산 연계 + 수수료. [근거 L5 신고매뉴얼]
- **가격 가드**: 게시자가 기준가 대비 허용 편차·유효기한 설정 → 협의 중 외부 지표 임계 초과 시 해당 RFQ 자동중지·양측 알림. 외부 지표는 가격 결정이 아닌 이탈 감지 가드로만 사용(가격 불관여 유지). 자동 호가매칭은 두지 않는다.

## K-2. 이해상충 통제 (차이니즈월) — [개발/운영] ★
나목 겸업 self-dealing 방지 [근거 L6 §10]: 나목 교환 기능이 마목 게시판 비공개정보(상대방 최저 수용가 등)에 접근 불가(정보격리·시스템 권한 분리), 관계자 수수료 동일, DSRV 연계 거래 시장감시 별도 플래그·정기 이해상충 보고. 교환하기/거래하기 화면·플로우 분리로 UI에서도 격리.

## L. 로그·감사 — [개발] (BE) ★ISMS 필수
행위로그·감사로그·API 로그. WORM·해시 무결성. 거래기록 15년, AML 5년, 개인정보 파기주기 분리.

## M. 관리자 기능 — [개발] (BE/FE)
요청 단일 승인/반려, 상태 변경, 사용자·지갑·거래 조회, ORG·KYC 상태 설정, 나목 재고·이해상충 감시.

## N. Travel Rule — [서드파티] (BE 연동) ★VASP 필수
100만원 이상 이전 시 송수신인 정보 교환. CODE 또는 VerifyVASP. 개인정보 국외이전 적법 근거·보호조치 [확인필요][로펌게이트].

# 5. 백엔드 / 프론트엔드 / 컨트랙트 개발 분류

## 5-1. 백엔드 (BE)
인증·세션·2FA, RBAC, Policy Engine(1차 검증)+수동검증 라우팅, 단일 승인 워크플로우. 지갑 추상화(주소 발급·조회·입금 감지·콜드 집행 요청 티켓·집행 상태·정합성 대사). 교환 엔진(RFQ·스프레드 비율·재고 차감 기록), 중개 엔진(의향 보드·가격가드·정산 연계). 원장/회계(내부 잔액↔온체인 정합, 증명서 데이터). 로그·감사. 연동 어댑터(사내 커스터디·올댓노드·외부 가격지표·KYT·Travel Rule·FDS).

## 5-2. 프론트엔드 (FE) — 웹 (적응형)
로그인/2FA, ORG·멤버·역할 관리. 홈 대시보드(자산·비중·콜드·재고). **교환하기(나목) 화면**(요청→비율 확인·수락), **거래하기(마목) 보드**(게시·협의·가격가드), 승인 대기함, 관리자 콘솔(요청·KYC·재고·이해상충 감시), 리포트·증명서. KYC 서류 업로드·심사 화면은 수기 전제로 MVP 제외.

## 5-3. 컨트랙트 (Contract) — MVP 불필요 ★
취급 자산이 ETH(네이티브)와 표준 ERC-20 스테이블코인(USDC·USDT)뿐. 송금은 ETH 네이티브 전송 또는 표준 ERC-20 transfer 호출. 자체 토큰·커스텀 컨트랙트 개발 불필요. 컨트랙트 개발 공수 ≈ 0. 인력을 BE/FE에 집중.

# 6. 네트워크 연결

## 6-1. 체인 전략
취급 자산 3종(ETH·USDC·USDT) 모두 Ethereum 메인넷 → **Ethereum 단일 체인**(v1 가정 유지). 주소 1개로 3종 수신(ETH 네이티브 + ERC-20 2종, 동일 주소).

## 6-2. 노드/RPC — 사내 올댓노드
잔액 조회·브로드캐스트·입금 감지(블록/주소 모니터링)를 사내 올댓노드로 구성. 외부 매니지드 RPC 미사용.

## 6-3. 온체인 연산 매핑 (ETH 네이티브 · ERC-20 스테이블코인)

| 기능 | ETH (네이티브) | 스테이블코인 (ERC-20) |
|---|---|---|
| 잔액 조회 | eth_getBalance | balanceOf (eth_call) |
| 입금 감지 | 블록 내 수신 트랜잭션 스캔(컨트랙트 경유 내부 tx 포함 여부 [확인필요]) | Transfer 이벤트 로그 / 주소 활동 |
| 출금 | value 전송(콜드 수동 서명·전송) | transfer 호출(콜드 수동 서명·전송) |
| 가스 | ETH 자체가 가스 → 출금 시 가스분 별도 확보 | 네이티브 ETH 가스 필요 → 발송(콜드 운영) 지갑 가스 충전 전략 |

## 6-4. 키관리·서명 · 콜드 (사내 커스터디)
키관리·서명·콜드 보관은 사내 커스터디. **전량 콜드·수동, 운영 핫월렛 없음.** 콜드 보관이 이용자보호법 시행령 §11 콜드 요건을 현행 운영으로 충족. 외부 커스터디 솔루션 도입 불필요.
확인 사항: (a) 콜드 집행 절차·SLA, (b) 가스 충전 주체, (c) 지원 자산·체인, (d) 집행 이중확인·키운영자 이원화.

# 7. 나목 교환 운영 전략 (자사 상대방 · 콜드 수동)

v1의 3모델(프린시펄/RFQ 중계/유동성 API) 중, **자사 상대방 프린시펄을 채택하되 거래소·MM으로 오인되지 않게 축소**한다.

- **채택**: DSRV가 교환 상대방(고객↔DSRV). 콜드 최소재고로 메우고 스프레드로 수익.
- **v1과의 차이(비MM·비거래소)**: 외부 거래소/LP 다중 소싱·자동 체결 없음. 교환비율은 **외부 지표 참조 + 고정 스프레드**(자체 시세산정 없음). 집행은 커스터디 콜드 건별 수동. 연속 양방향 호가 금지(단건 RFQ·블록딜). 재고는 소량·콜드.
- **이해상충**: 마목 게시판 겸업이므로 차이니즈월(K-2) 적용.
- 필요: 재고 한도·재보충(콜드) 절차, 스프레드 산정 규칙(외부지표 소스·갱신주기·이탈 임계), VASP 나목 신고.
- 경계 소명: '자동체결 거래소·MM 아님'을 자기재고·수동집행·건별승인·외부지표 스프레드·비연속 호가로 소명. FIU 사전면담(G0). [로펌게이트]

# 8. 마목 중개(게시판) MVP 스펙

의향 등록 보드: 회원 기관이 자산/수량/희망조건/유효기간으로 매도·매수 의향 등록. **가격 이탈 자동중지(price-guard) 옵션** 포함. 매칭: 자동 호가매칭 없음. 게시판 노출·조회 + 당사자 협의(DSRV 비참여·기록만). 체결·정산: 합의 시 각자 이전 지시 → Policy Engine(1차)·단일 승인 → 커스터디 콜드 수동 이전(양건 확인 후 순차) → (대상 시)Travel Rule → 수수료 1% 양측. 리포팅·증명서: 체결 내역·잔고증명·거래 증빙.

# 9. MVP 범위 / 비범위

## In Scope (심사 통과 + 운영 최소선)
인증·2FA · RBAC · Policy Engine(1차)+수동검증 · 단일 승인 · 수탁지갑(**100% 콜드·수동**) · KYC 상태 게이팅(수기) · OFAC/KYT(사내 확인 후) · Travel Rule · FDS 연동 · 홈 대시보드(외부 가격지표) · **교환하기(나목·자사 콜드 재고·외부지표 스프레드)** · **거래하기(마목·게시판+가격가드)** · 차이니즈월 통제 · 로그/감사 · 관리자.
**직무분리 완화 보완통제·콜드 수동집행 가용성(4-eyes·SLA·키운영 이원화·DR)은 In Scope.**

## Out of Scope (2차)
핫월렛·자동 정산엔진·자동 호가매칭·자동 체결·자체 시세피드/가격형성 · 연속 양방향 호가(MM)·API 자동체결 · 외부 LP 다중 라우팅 · 멀티체인 · 자동 KYC(벤더) · 온체인 거버넌스 컨트랙트 · 모바일 앱 · 스테이킹/수익상품 · 외부 VASP 참여(§28) · 개인·외국 고객.

# 10. 권장 우선순위 (인력 가정)

기반(必先): 인증·2FA·RBAC·ORG 가입 + 로그/감사 골격. → 커스터디 연동 + 지갑 레이어(주소 발급·서명·**콜드 집행 티켓**·입금 감지·정합성. 핫/스윕 없음. 노드는 사내 올댓노드). → Policy Engine(1차)+수동검증 + 단일 승인. → **교환하기(나목) 데스크 + 대시보드(외부 가격지표)**. → **거래하기(마목) 게시판 + 가격가드 + 차이니즈월 권한 격리**. → 컴플라이언스 연동(OFAC/KYT·Travel Rule·FDS). → 리포팅/증명서. 컨트랙트 개발 인력 불필요 → BE·인프라·컴플라이언스에 재배치.

전제: 나목·마목은 커스터디 **내부 지갑 간 이전**, 외부 주소 미취급, 집행 100% 콜드·수동. 보유 인증 = ISMS-KISA-2026-044(ISMS).

## 1. 대응 방침 한 줄

개발을 최소화한다. 규제 통제라 "안 함"이 아니라 **"안 하는 근거를 심사관이 납득하게 문서로 남긴다"**. 6개 지적 중 4개는 개발에서 빼고(근거 문서화), 2개만 저비용 개발로 남긴다.

## 3. 화면설계 반영 사항 (storyboard v3 개정 지시)

개발 최소화 방침을 화면에 반영. **추가하지 않는 것**과 **문구·표기로만 반영하는 것**을 구분한다.

### 3.1 화면에서 빼거나 만들지 않는 것

| 대상 | 조치 |
|---|---|
| 화이트리스트 등록·관리 화면 | **신규 생성 안 함.** EXC-01·BRK 흐름에서 "화이트리스트 확인" 단계·필드 넣지 않음 |
| 어드민 조회의 상대방정보·주소·잔액 컬럼 | **표시 안 함.** ADM-04·ORG/KYC 조회 화면 노출항목에서 제외(정의서에 "미표시" 명시) |
| 원장 변경 화면 | **신규 생성 안 함.** ADM-04는 "조회 전용" 유지 문구 강화 |
| 긴급 출금중단·거래정지 전용 화면 | **신규 생성 안 함.** 아래 플래그로 대체 |

### 3.2 화면에 반영(추가·수정)하는 것

| 화면 | 반영 내용 | 근거 |
|---|---|---|
| **EXC-03 교환 승인** | 승인(DSRV 단일)과 **집행 서명(콜드 2인 멀티시그)을 분리 표기**. "단일 승인 ≠ 단일 집행" 주석 | 2.7.2·2.2.2 |
| **EXC-04 / BRK-05 집행** | 콜드 출고 단계에 **"2인 서명(멀티시그)"** 라벨 명시 | 2.7.2 |
| **ADM-02 관리자 콘솔** | 기존 "이상징후" 옆에 **월렛/키 접근 알람 축** 추가(값은 Slack 라우팅에서 유입, 카운터·목록만 표시). 신규 위젯 최소 | 2.11.3 |
| **ADM-03 요율·정책** | **거래정지 플래그(거래가능 on/off)** 정책값 1개 추가. 변경도 maker-checker 이력 | 2.11.1 |
| **ADM-04 통합 로그** | ① "**조회 전용·원장 직접변경 미구현**" 명시 문구 ② 로그 항목에 **기록 금지 필드(개인키·passphrase·시드)** 표기 ③ 조회 노출항목에서 개인정보·주소·잔액 제외 | 2.9.1·2.9.4·2.6.3 |
| **AUTH-01 / 계정** | (선택) 계정정보 변경 시 MFA 재인증 지점 표기. 화이트리스트 등록이 없어졌으므로 "정보변경" 재인증 대상은 계정정보로 한정 | 2.10.4 |

### 3.3 화면 문구로 못박을 방어 근거 (examiner 대응)

각 화면 비고란 또는 인증범위정의서에 다음 3줄을 배치한다.
1. **화이트리스트 미적용** — "교환·중개는 내부 커스터디 지갑 간 이전, 외부 주소 미취급. 외부 반출은 기존 커스터디 출금 절차로만."
2. **원장 직접변경 미구현** — "원장 조회 전용. 파생값은 온체인+커스터디 실잔액 3면대사로 검증. 정정은 감사로그 남는 매뉴얼 절차."
3. **긴급대응** — "수동집행 구조상 승인 중단=집행 정지. 신규 접수는 거래정지 플래그 차단. 통지는 절차서."

## 4. 확인 필요 (미해결)

| # | 항목 | 갈림 |
|---|---|---|
| 1 | 마목 정산이 100% 내부 지갑 간인지 | 외부 반출 흐름이 있으면 그 건은 커스터디 출금(화이트리스트) 적용 |
| 2 | 온체인 감시 수단 | 자체 노드 webhook vs 외부 서비스(위탁 현황표·2.3.1 등재 필요) |
| 3 | 24×365 운영 주체 | 자체 당직 vs 관제 위탁(2.11.1 계약 반영) |
| 4 | ISMS vs ISMS-P | ISMS면 3장(D절 개인정보 22항목) 심사대상 제외. 개보법 의무·스펙은 잔존 |
| 5 | ETH(네이티브)·USDC·USDT 자산별 서명방식 | 서명방식 매트릭스 확정용(네이티브 전송/ERC-20 transfer 구분) |

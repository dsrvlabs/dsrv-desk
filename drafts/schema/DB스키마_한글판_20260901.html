DB 스키마 — 한글판 v0.6 · 2026-09-02

교환·중개 콘솔의 데이터 구조를 기획 관점에서 한글로 정리한 문서 · 6개 영역 · 총 29개 테이블 · 취급자산 ETH·USDC·USDT · 체인 Ethereum 단일 · PK=기본키(그 테이블의 대표 식별자) · FK=외래키(→ 다른 테이블 참조)

이 문서가 다루는 것

기관 고객이 스테이블코인을 DSRV와 직접 교환(나목)하거나, 고객 간 교환을 DSRV가 게시판 방식으로 중개(마목)하는 콘솔의 데이터 구조다. 카드 하나가 테이블 하나이고, 카드 제목은 한글명 + 영문 테이블명 + 주로 쓰이는 화면(우측 회색)이다.

여섯 영역으로 나뉜다: ① 신원·인증 누가 쓰는가 · ② 지갑·자산 무엇을 보관·이동하는가 · ③ 나목 교환 · ④ 마목 중개 · ⑤ 컴플라이언스·감시 승인·알람의 처리함 · ⑥ 정책·로그·회계 정책값과 증적.

본문의 T1~T8·X3은 관리자 처리함의 아이템 유형 번호로, 상태 전이 문서(states.html)와 같은 번호다. [확인필요]·[결정필요]는 아직 정하지 않은 사항의 표시다.

데이터 흐름 한눈에

나목 (직접 교환)교환 요청 → 스프레드 견적 → 교환 승인 T1 → 교환 집행·완료
마목 (중개)거래의향(RFQ) → 신청 → 조건 확정(딜) T2 → 이전·정산
입출금입금 트랜잭션(자동 감시 T4) · 출금·이전 요청(서면 접수 T3)
승인·알람모든 승인 대기·워닝은 처리함 아이템 한 테이블로 모여 관리자가 종결

이 DB에 없는 것 (경계)

  • STR(의심거래보고) 작성·보고 — 별도 AML 시스템에서 수행. 콘솔에는 처리함 결과코드 'STR 이관'까지만 기록
  • KYC 심사 도구 — 심사는 별도 시스템, 콘솔은 상태·기록만 보관
  • 고객 대상 거래보고서 — 발급하지 않음. 조회·집계는 관리자 CSV로 대체
  • 출금 화이트리스트 관리 — 기존 커스터디 정책·시스템 그대로 사용

DB 스키마 — 한글판 v0.7 · 2026-09-02

교환·중개 콘솔 DSRV Desk(고객)·DSRV Admin(관리자)의 데이터 구조 · 6개 영역 · 총 29개 테이블 · 취급자산 ETH·USDC·USDT · 체인 Ethereum 단일 · 개발자가 처음 읽어도 이해되도록 용어·기호를 앞에서 먼저 풀고(§0), 카드마다 테이블의 역할 한 줄을 붙였다.

이 문서가 다루는 것

국내 법인 고객이 DSRV와 직접 가상자산을 교환하거나(이 문서에서 "직접 교환", 법령 용어로는 나목), 고객끼리의 교환을 DSRV가 게시판 방식으로 중개하는("게시판 중개", 법령 용어 마목) 서비스의 데이터 구조다. 모든 실제 자산 이동은 기존 커스터디팀이 콜드월렛에서 사람이 수동으로 실행하고, 이 시스템은 요청·승인·기록을 담당한다.

여섯 영역으로 나뉜다: ① 신원·인증 누가 쓰는가 · ② 지갑·자산 무엇을 보관·이동하는가 · ③ 직접 교환(나목) · ④ 게시판 중개(마목) · ⑤ 컴플라이언스·감시 승인·알람의 처리함 · ⑥ 정책·로그·회계 정책값과 증적.

본문에 나오는 약어·기호(T1~T8·X3, G-3, CSV ①~⑥, KYT·BLF 등)는 모두 §0 참조 안내에 정의가 있다. 본문에서는 처음 보는 기호가 나오면 §0의 어느 표를 보면 되는지 함께 적었다.

카드 읽는 법

카드 1개= 테이블 1개. 제목은 한글명 + 영문 테이블명, 오른쪽 회색은 이 테이블을 주로 읽고 쓰는 화면 코드(§0-C 표).
회색 띠테이블의 역할 — 행 1개가 무엇에 해당하고 언제 만들어지는지.
PK기본키. 그 테이블의 행을 유일하게 식별하는 값.
FK외래키. 다른 테이블의 PK를 가리킨다. 설명의 → 대상 테이블이 참조 대상.
· (점)일반 컬럼. 설명 끝의 / 로 구분한 값은 허용값(enum) 후보. 전체 목록은 부록.
태그[확인필요] 아직 사실 확인 전 · [결정필요 ①~⑤] 기획·법무가 결정해야 함(번호는 비고 참조) · [로펌게이트] 변호사 판단이 필요해 질의로 넘길 사항. 세 태그가 붙은 값은 바뀔 수 있는 값이니 설정으로 빼 둔다.

설계 원칙 3가지 — ⓐ 자동은 검증·산정·아이템 생성까지, 승인·거절·종결은 사람이 한다(자동 체결 없음). ⓑ 본인이 올린 건은 본인이 승인할 수 없다. ⓒ 모든 상태 변경은 감사로그(AUDIT_LOG)에 남고 수정·삭제할 수 없다.

이 DB에 없는 것 (경계)

  • STR(의심거래보고) 작성·보고 — 별도 AML 시스템에서 수행. 이 DB에는 처리함 결과코드 'STR 이관'까지만 남는다
  • KYC 심사 도구 — 심사는 별도 시스템. 이 DB는 결과 상태와 다음 재이행 일정만 보관
  • 고객 대상 거래보고서 — 발급하지 않음. 조회·집계는 관리자용 CSV 6종으로 대체
  • 출금 화이트리스트 관리 — 기존 커스터디 정책·시스템을 그대로 사용
  • 가격·오더북·자동 매칭 — 없음. 직접 교환 비율은 외부 지표 + 고정 스프레드, 게시판 중개는 당사자가 정한 조건 그대로

A. 용어 사전본문 등장 순이 아니라 주제별
용어뜻
나목 · 마목가상자산사업자 업무 유형을 법령이 가~마목으로 열거한 데서 온 이름. 나목 = 가상자산을 다른 가상자산과 교환하는 행위(이 서비스에서는 고객↔DSRV 직접 교환). 마목 = 매매·교환을 중개·알선·대행하는 행위(이 서비스에서는 게시판 중개). 출처: 가상자산이용자보호법 제2조 제2호 나목·마목 (knowledge/01a/L6 원문 확인)
직접 교환고객이 DSRV를 상대방으로 교환하는 것(= 나목). DSRV 자기 재고(교환재고 풀)에서 내주고, 비율은 외부 시세 지표에 고정 스프레드를 더해 시스템이 산정한다. 오더북·자동 체결은 없다.
게시판 중개고객 A가 "이 수량을 저 수량과 바꾸겠다"는 조건을 게시하고, 고객 B가 그 조건 그대로 신청하면 A가 수락해 거래가 확정되는 방식(= 마목). DSRV는 가격에 관여하지 않고, 게시 검증·양측 KYC 담보·정산 연계·수수료 수취·기록을 맡는다.
거래의향 (RFQ)게시판에 올린 게시 1건. RFQ는 Request for Quote의 약자지만 여기서는 "게시글" 정도로 읽으면 된다. 테이블 RFQ_INTENT.
딜 (DEAL)게시자가 신청을 수락한 순간 성립하는 확정 거래. 수락 = 즉시 확정·법적 구속력·수수료 발생. 별도 확정 화면이 없다.
스프레드외부 지표 비율에 DSRV가 얹는 고정 마진(%). 직접 교환의 수익원. 화면에서는 비율과 항상 별도 항목으로 표시한다.
가용 풀 (POOL)직접 교환에 내줄 수 있는 DSRV 자기 재고 수량. 콜드월렛 보관. 0이면 교환 불가.
KYC · CDD · EDDKYC = 고객확인. CDD = 일반 고객확인, EDD = 고위험 고객에 대한 강화된 고객확인. 심사는 별도 시스템에서 하고 이 DB에는 결과만 둔다.
PEP · 실제소유자PEP = 정치적 주요인물(고위험 분류 대상). 실제소유자 = 법인을 실질적으로 지배하는 개인(확인 의무 대상).
KYTKnow Your Transaction. 입금·교환 트랜잭션의 자금 출처·경로 위험도를 점수로 매기는 자동 분석.
BLF블랙리스트 필터. 지갑 주소가 제재 대상·블랙리스트에 올라 있는지 대조하는 검사. 적중 = 걸림.
STR의심거래보고. 자금세탁이 의심되는 거래를 금융정보분석원(FIU)에 보고하는 절차. 보고 대상 고객이 이를 알게 하면 안 된다(누설 금지) — 고객 화면·통지 문구에 STR 관련 표기를 절대 넣지 않는 이유.
트래블룰가상자산을 이전할 때 송신인·수신인 정보를 함께 확인·전달해야 하는 규제 요건. 테이블 TRAVEL_RULE.
자동검증 · 에스컬레이션자동검증 = 한도·잔고·BLF·KYT를 시스템이 먼저 검사하는 1차 필터. 결과가 '주의' 이상이면 자동 거절하지 않고 에스컬레이션(우선 검토 대상으로 표시)해서 사람이 판단한다.
처리함 (INBOX)관리자 홈(ADM-02)의 작업 목록. 승인·확인·조사가 필요한 일이 생기면 시스템이 '아이템'을 만들어 쌓고 관리자가 종결한다. 유형은 §0-B.
격리 · 동결격리 = 위험 신호가 있는 입금을 고객 잔고에 반영하지 않고 격리 지갑에 따로 두는 것. 동결 = 소명이 인정되지 않거나 제재 적중으로 자산 이동을 막은 상태.
지연발효처음 쓰는 출금 주소는 등록 후 일정 시간(24시간)이 지나야 출금 승인이 가능해지는 보호장치. 계정 탈취 시 즉시 출금 피해를 막는다.
콜드 · 핫 · 스윕콜드월렛 = 인터넷과 분리된 지갑(수탁자산은 100% 콜드). 핫월렛 = 온라인 지갑. 스윕 = 핫월렛 잔고를 콜드로 옮기는 작업. 핫 비중이 20%를 넘으면 스윕 경고.
2인 멀티시그콜드월렛 출고에 서명자 2명이 필요한 방식. 서명은 화면 밖 커스터디 절차이고 DB에는 서명자 2명만 기록.
명세 대사 · 3면 대사명세 대사 = 집행 명세(주소·자산·수량)와 온체인 결과(txhash)가 일치하는지 확인. 일치해야 '완료'. 3면 대사 = 내부 장부·온체인 잔고·콜드월렛 기록 세 값을 맞춰보는 정기 점검.
구분회계고객 수탁자산과 DSRV 자기 자산·수익을 계정으로 분리해 집계하는 것. 스프레드 수익과 중개 수수료 수익도 서로 다른 계정.
WORM · 해시 · NTP감사로그 보존 요건. WORM = 한 번 기록하면 수정·삭제할 수 없는 저장. 해시 = 기록 위변조 검증값. NTP = 표준시 동기화(기록 시각 신뢰성).
PAM특권계정 관리. DSRV 관리자 행위는 전용 세션에서 녹화·감사되며 권한을 분기마다 재검토한다. 내부 정책이고 화면에는 표시하지 않는다.
MFA · TOTP · 백업코드MFA = 2차 인증. TOTP = Google Authenticator 방식 시간 기반 일회용 코드. 백업코드 = 인증 기기를 잃었을 때 쓰는 1회용 코드(6개 발급).
마스킹화면·CSV에서 일부만 보이게 가리는 것. 상호는 확정 전 첫 글자만, 이메일은 CSV에서 가림, 주소·해시는 앞 0x+4자…뒤 4자.
서면 접수출금·이전은 고객 화면에 기능이 없고, 고객이 문서로 신청하면 관리자가 시스템에 대신 등록한다는 뜻.

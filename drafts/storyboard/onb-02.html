· 전역 이동 프레임(브랜드 패널 · 푸터 · 뒤로가기)의 동작은 계정 활성화 1/3 비밀번호 설정(ONB-01)의 표와 같다. 다른 점 없음.
· 진입 계정 활성화 1/3(ONB-01) [다음] 성공 직후. 비밀번호 저장까지 끝난 뒤 초대 메일 링크를 다시 클릭한 경우에도 이 화면으로 들어온다.
1
2FA QR (표시 전용)
값 계정별 TOTP 시크릿으로 QR을 만든다. 재생성은 연속 실패 {정책값 5회} 도달 시에만 한다.
등록 완료 상태 QR과 설정 키를 흐리게 하고 "등록됨" 배지를 붙이며 6칸을 비활성으로 둔다.
[디자인 요청] 등록 완료 상태 표시는 시안에 없다.
근거 ISMS 2.5 · F-5
2
설정 키 (표시 전용 · 수동 입력용)
값 QR과 같은 시크릿을 Base32 문자열로 보여준다. 등록 확정 후에는 어느 화면에도 다시 노출하지 않는다.
근거 ISMS 2.5 · QR 대체 수단
화면 이동 · 인터랙션
설정 키 필드클릭 · 드래그텍스트 선택만(편집 불가)
3
6자리 인증 코드 입력 (6칸 · 자동 검증)필수
입력 가능 2FA 등록 확정 전에만 가능하다. 등록 완료 상태(ONB-03에서 복귀)면 비활성이고, 검증 중에는 읽기 전용이다.
허용 문자 숫자만 받고 한 칸에 1자를 넣는다. 입력하면 다음 칸으로 포커스를 옮긴다.
검증 6번째 자리를 채우는 즉시 서버에 검증을 요청한다. 확인 버튼과 Enter는 두지 않는다.
실패 6칸을 초기화하고 첫 칸에 포커스를 주며 오류 칩에 {남은 횟수}를 표기한다. 실패는 감사로그에 남긴다. [확인필요: 연속 실패 임계 — 현재 고정 5회]
연동 성공하면 2FA를 확정하고 복구 코드를 생성해 ONB-03으로 넘긴다. 연속 실패가 {정책값 5회}에 도달하면 시크릿을 재생성해 항목 1·2의 QR과 설정 키 값을 교체하고 재등록 안내 칩을 띄운다(토큰은 무효화하지 않는다).
근거 ISMS 2.5 · F-5
화면 이동 · 인터랙션
6칸 코드 — 6자리 완성자동 검증("확인 중…" · 중복 검증 차단) → 성공 시 2FA 확정 · 복구 코드 생성 · ONB-02 완료 기록 · 감사로그성공 → 복구 코드 저장(ONB-03) / 실패 → 칩 · 6칸 초기화 / {정책값 5회} 도달 → 시크릿·QR 재생성 · 칩 안내
상세내용
32FA 등록 · 시크릿
표준 TOTP(RFC 6238)를 쓰고 QR과 설정 키는 같은 시크릿이다.
등록 확인 6자리 코드 1회 검증 성공으로 확정하고 실패는 감사로그에 남긴다.
시크릿 수명 등록 확정 전까지 같은 값을 유지하고 확정 시 복구 코드(ONB-03)를 함께 생성한다.

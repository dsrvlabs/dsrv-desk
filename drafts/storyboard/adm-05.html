데이터 다운로드 — CSV 6종필수
노출 6종 각각 버튼 1개로 항상 보인다(대표 핀 = 영역 전체). 어드민 역할이 1종이라 6종 모두 같은 조건으로 보인다.
클릭 가능 항상 활성이다. 같은 종류를 생성하는 동안만 비활성이고 다른 종류는 함께 받을 수 있다.
확인 사항 없다. 확인 다이얼로그를 띄우지 않는다.
액션 조회성 데이터는 화면 목록을 두지 않고 전부 CSV로 뺀다. 기간·조건 선택 없이 생성 시점 기준 전체 기간 스냅숏을 동기 생성한다. 모든 다운로드는 열람 기록(⑥)에 남는다. 컬럼 정의는 부록을 본다.
· ③ 콜드 이전 목록에 반환·수수료 스윕 행 유형이 추가됐고 명세 해시를 포함한다(2026-09-04).
· ⑤는 '3면 대사'다 — 내부 장부 ↔ 온체인 ↔ 커스터디 콜드 기록 세 값을 자산 묶음 4개 전부에 대해 스냅숏한다. 2면(장부↔온체인)이 아니다.
· 개인식별정보는 CSV에서도 마스킹한다.
[확인필요] 구현 화면의 ② 설명이 "KYT 점수·BLF 결과를 포함한 감사용 자료"인데, BLF·KYT 임계와 판정은 커스터디 소유로 정리했다(2026-09-07(21) · 종전 kyt_blf_thr → escalation_thr 대체). 이 CSV에 KYT 점수·BLF 결과가 실제로 들어가는지, 들어간다면 어느 값을 받아 적는지 확인이 필요하다.

· CSV ④ 원장은 4분할이다 — 고객 수탁 / 운영 / 나목 교환 최소재고 / 에스크로 전용지갑. 09 §0 자산 묶음 4개와 정합.

비고
· DSRV 내부 관리자 화면(고객사 노출 없음). 어드민은 처리함(ADM-02) · 설정(ADM-03) · 기관 · 가입자(ADM-04) · 데이터 다운로드(ADM-05) 4화면이다. 이 화면은 2026-09-16 구현 화면 기준으로 처리함(ADM-02)에서 분리했다.
· ①~⑥ 번호는 바꾸지 않는다. 지침 제42조·DB 스키마·케이스분기·운영 매뉴얼이 'CSV ⑥ 열람 기록'처럼 번호로 참조한다. 카드 이름만 구현 화면 문구를 따랐다.
· 다운로드 자체가 열람 기록이다 — ⑥을 받는 행위도 ⑥에 남는다(지침 제42조④).
· 다운로드 이력을 보는 화면은 두지 않는다(2026-09-02(11) 편의기능 축소). 이력은 ⑥ CSV로만 본다.
· 연결: ① 기관·가입자 목록 원천 = 기관 · 가입자(ADM-04) · ②③ 원천 = 처리함(ADM-02) ①② · ⑤ 3면 대사 불일치 알림 = 처리함 ④ 운영 알림.
· [확인필요] ② 거래 요청 CSV의 KYT 점수·BLF 결과 포함 여부 — 개발에 회신 요청함(drafts/48 확인 A번): 실제로 들어가는지, 들어간다면 어디서 받아오는지, 안 들어가면 화면 설명 문구를 고쳐야 한다(항목 1 참조) · 각 CSV의 컬럼 정의(부록) · 생성 시간이 긴 CSV의 동기 생성 한계.

초대 토큰 검증필수
· 초대 이메일 링크의 일회성·유효기간 토큰 검증
· 셀프가입 없음(초대 기반 ORG) · 만료 시 재발급
근거 32 §2 ONB-01 · 초대 기반
2
비밀번호 본인 설정필수
· 담당자가 직접 설정(회사가 초기 비밀번호를 만들어 전달하지 않음)
· 비밀번호 규칙 4개 항목 안내 노출 · 원문 저장·전송 없음 · 같은 안내문구를 비밀번호 수정(DASH-02)에서도 재사용
근거: 계정 활성화·비밀번호 설정 화면 · 정보보호 관리체계(ISMS) 인증기준 2.5.3·2.5.4(비밀번호 관리)
화면 이동 · 인터랙션
새 비밀번호 · 확인 입력비밀번호 규칙(4항목) 검증 — 위반 시 다음 진행 불가화면 내 (이동 없음)
3

· 전 권한자 MFA 의무
근거 ISMS 2.5 · F-5
화면 이동 · 인터랙션

4
백업코드·활성화 완료필수
· 백업코드 발급(기기 분실 대비) · 저장 안내
· 활성화 완료 → 로그인 이동
근거 ISMS 2.5 세션·인증 복구
화면 이동 · 인터랙션
[활성화 완료 → 로그인] 버튼클릭 — 비밀번호 설정·2FA 등록 완료가 전제 · 백업코드 발급 후 활성화 확정로그인(AUTH-01) 이동
상세내용
2비번 방식 근거
· '초기 비밀번호 생성·전달' 대신 활성화 링크 → 본인 설정
· 비밀번호가 서버·이메일에 평문으로 존재한 적 없음
· 심사기관 설명·감사 대응 용이
32FA 등록·복구
· Google Authenticator 사용 — 시간 기반 일회용 비밀번호(TOTP, RFC 6238) 표준 · 로그인·민감행위 재인증에 사용
· 등록 실패·우회 시도는 감사로그 기록
4백업코드 취급
· 기기 분실 시 로그인 2FA 입력칸에 그대로 입력(AUTH-01 · 별도 화면 없음)
· 1회용 — 사용 즉시 폐기 · 사용 이력 로그
· 재발급은 2FA 재설정(초대 재발송→ONB-01 재수행) 완료 시 자동 — 이전 코드 전량 폐기
비고
· 가입 완료 직후 1회성 계정 활성화 화면. 초대 이메일 링크 → 비밀번호 본인 설정 + 2FA(QR) 등록 → 백업코드 → 로그인.
· 이전: 초대 이메일(ONB-00) · 다음 화면: 로그인(AUTH-01)

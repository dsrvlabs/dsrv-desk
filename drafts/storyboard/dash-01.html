1
내 거래 현황필수
· 나목 교환 + 마목 중개 통합 뷰(진행중·승인대기·완료)
· 완료 지표 = 누적 전체 건수 · 하단 목록 = 전체 거래(시간순)
· 목록 컬럼: 구분 · 수량 · 교환코인 · 비율 · 상태 — 비율은 {받는코인}/{주는코인}(notation 규칙)
· 승인 대기 건도 비율 표기 — 나목은 수락으로 고정된 확정 비율, 마목은 양사 약정 비율
· 행 선택 → 해당 거래 상세
근거 32 §3 DASH-01 · IA 대시보드
화면 이동 · 인터랙션
거래 목록 행클릭 — 구분·상태별 해당 거래 상세로나목 진행중 → EXC-03 · 나목 완료/보류 → EXC-04 · 마목 내 게시(게재중·신청접수) → BRK-06 · 마목 내 신청(수락 대기·거절·만료·회수) → BRK-07 · 마목 확정·완료(양측) → BRK-05
2
지갑 잔고 · 지갑 주소필수
· ETH·USDC·USDT 잔고 — 조회 전용(자산 이동 없음), 출금/이전은 온라인 기능 없이 커스터디 서면 요청 절차
· '콜드 100%·원장 분리' 고지는 잔고 하단 한 줄로만 표시
· 지갑 주소는 잔고 하단에 자산별 전문(全文) 표시 — 말줄임·QR 버튼 없음, 항목명은 코인·체인(예: USDT · Ethereum)
· 입금 유의 문구는 화면 미표기 — 입금 예외 처리 기준은 상세 참조
· 나목 교환 가용 풀(운영자산) 표출은 교환 요청(EXC-01)에서
근거 L7 §11(콜드) · L6 구분회계 · 32 §3 WAL-01
3
계정·보안 관리필수
· 비밀번호 수정(DASH-02) — 현재 비밀번호 확인 후 변경(MFA 재인증 없음) · 2차 인증 재설정(DASH-03) — 재인증 입력 없이 본인 이메일 링크 방식(기기 분실 대비)
· 세션·기기 관리 화면 없음 — 계정당 1세션 원칙(AUTH-01)이라 관리 대상 목록이 없음, 비밀번호 변경 시 전체 세션 로그아웃으로 갈음
근거: 정보보호 관리체계(ISMS) 인증기준 2.5(계정·인증 관리)·2.10.4(중요정보 변경 시 재인증)

상세내용
1통합 거래 뷰
· 나목(DSRV 상대 교환)과 마목(당사자 중개)을 한 화면에서 상태별로 요약
· 승인 대기 = 나목: DSRV 거래 진행중(약 2영업일) / 마목: 상대방 수락·DSRV 확인 대기
2조회 전용 · 집행 분리
· 출금/이전 집행은 어드민 홈(ADM-02) 처리함 승인 + 콜드 2인 멀티시그(커스터디 운영절차)
· 원장 분리·풀 구조 상세는 거래구조 문서 참조
· 입금 예외 귀속: 오입금(B3)·컨펌 중(B4)·스팸(B5)은 잔고 미반영·안내, KYT 고위험(B1)·제재 적중(B2)은 격리·동결·STR — 판정·처리는 ADM-02 처리함, 고객 화면에는 상태만 노출 · 오입금 반환 가스비 부담 주체 [확인필요]
32FA 재설정 흐름
· 재설정 흐름·백업코드 취급 상세는 DASH-03 참조
· 백업코드 로그인 직후에는 홈 상단에 재설정 권고 배너 노출
4활동 로그 성격
· 원본 로그는 서버 보관 — 화면 노출 최소화
· 관리자 알람·워닝(ADM-02)과 별개 — 이용자 관점 이력
비고
· 로그인 성공 후 첫 페이지. 상단 고정 메뉴(GNB) + 내 거래 현황 + 지갑 잔고·주소 + 계정·보안 + 활동 로그(CSV).
· 지갑 별도 화면 없음(구 WAL-01~03 삭제) — 잔고·주소는 이 화면, 출금/이전은 커스터디 서면 요청 절차, 화이트리스트는 내부 관리.
· ISMS 2.10.4(중요정보 변경 시 재인증)는 현재 비밀번호 확인으로 충족한다고 보되 심사 시 해석 [확인필요].

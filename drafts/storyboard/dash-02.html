진입 · 전역 이동
· 전역 이동 프레임(브랜드 패널 · 푸터 · 뒤로가기)의 동작은 계정 활성화 1/3 비밀번호 설정(ONB-01)의 표와 같다. 다른 점 없음(브랜드 패널에 'DSRV 서비스 소개 보기 →' 링크가 없는 것도 ONB-01과 같다). 로그인 상태 화면이지만 콘솔 상단 메뉴(GNB)와 기관 배지가 없어 다른 콘솔 화면으로 바로 갈 수 없고 로그아웃 메뉴도 없다.
· 진입 대시보드(DASH-01) 계정·보안 영역의 '비밀번호 수정' 카드 클릭.
· 나가기 [취소] 또는 변경 완료 → 대시보드(DASH-01). 그 외 이동 경로 없음.
1
기존 비밀번호 입력필수
입력 가능 항상 가능하다.
허용 문자 제한을 두지 않는다. 일치 여부만 보므로 문자 필터가 필요 없다.
검증 [다음] 제출 시 서버가 일치를 확인한다. 클라이언트는 빈칸 여부만 본다.
실패 이 필드만 초기화하고(새 비밀번호·확인 값은 유지) 필드 아래 인라인 ⚠를 띄운다. 연속 불일치는 AUTH-01 통합 실패 카운터에 합산하고 {정책값 5회} 도달 시 로그아웃 + 계정 잠금.
연동 세 필드 중 하나라도 비어 있으면 [다음]을 비활성으로 둔다.

2
새 비밀번호 입력필수
입력 가능 항상 가능하다.
허용 문자 영문 대·소문자 · 숫자 · 특수문자 !@#$%^&*()만 받고 그 외 문자는 입력 시점에 무시한다. 길이는 8~20자로, 20자를 넘는 입력은 받지 않는다.
검증 키 입력마다 입력된 값 전체를 대상으로 규칙 ①~④(항목 4의 안내문 4줄)를 판정한다. 규칙 ② 비교 대상은 로그인 계정 이메일이다. 검증은 이 입력창에서만 하고 제출 시 서버가 규칙을 다시 검증하지 않는다.
실패 포커스 아웃 시 미충족 규칙이 남으면 인라인 ⚠를 띄우고 [다음]을 비활성으로 둔다. 제출 시 기존 비밀번호와 같으면 인라인 ⚠를 띄운다(비교 범위는 직전 1회 · 해시 1개 보관).
연동 값이 바뀌면 항목 3의 일치 비교를 다시 수행한다.
저장 단방향 해시와 salt로만 저장한다.

[다음] 버튼 (= 비밀번호 변경 저장)필수
노출 항상 보인다.
클릭 가능 세 필드가 모두 채워지고 새 비밀번호가 규칙을 통과했을 때 활성이다(일치 여부는 제출 시 판정).
확인 사항 서버가 기존 비밀번호 일치와 새 비밀번호가 기존과 다른지만 확인한다. 비밀번호 규칙은 다시 검증하지 않고, 확인 다이얼로그와 2차 인증 재입력은 없다.
액션 비밀번호를 단방향 해시와 salt로 저장하고, 타 기기 세션을 전체 로그아웃하며(현재 세션 유지) 변경 이력을 감사기록에 남기고 통합 실패 카운터를 초기화한 뒤 DASH-01로 복귀해 토스트를 띄운다.
[디자인 요청] 시안 라벨 '다음'을 '변경' 등으로 조정한다.

상세내용
1본인 확인 방식
본인 확인 기존 비밀번호 확인을 ISMS 2.10.4(중요정보 변경 시 재인증)의 충족 수단으로 해석한다.
오류 노출 이미 인증된 세션이므로 어느 필드가 틀렸는지 노출해도 된다.
잠금 AUTH-01 통합 실패 카운터에 합산하고 이 화면 전용 카운터는 두지 않는다.
4안내문구 정합
규칙 동일 규칙 판정(조합·길이 8~20자·이메일 동일 문자·동일 문자 반복·허용 특수문자)은 계정 활성화(ONB-01)의 새 비밀번호 입력과 같다.
검증 위치 규칙 판정은 입력창에서만 하고 서버는 기존 비밀번호 일치 확인과 저장만 한다.
5변경 후 처리(백엔드)
세션 타 기기 세션을 전체 로그아웃하고 현재 세션은 유지한다. 계정당 1세션이라 타 세션이 없는 것이 정상이며 방어적 처리다.
기록 변경 이력을 감사기록에 남기고 비밀번호는 단방향 해시와 salt로만 저장한다.
통지 이메일 통지 6종에 없으므로 변경 알림 메일은 보내지 않는다.

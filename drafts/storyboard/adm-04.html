1
기관명 입력필수
입력 가능 항상 가능하다. 선택 목록이 아니라 자유 입력이다(신규 기관 등록). 플레이스홀더는 "기관명"이다.
허용 문자 한글·영문·숫자·공백·괄호·마침표만 받고 2~50자다. 초과 입력은 무시하고 앞뒤 공백은 자동으로 지운다.
검증 ① 허용 문자로 2~50자일 것 ② 이미 등록된 기관명이 아닐 것. ①은 포커스 아웃 시 클라이언트가, ②는 [초대 발송] 클릭 시 서버가 본다.
실패 처리 ① 위반 → 빨간 테두리 + ⚠ "기관명은 2~50자 한글·영문·숫자로 입력해 주세요". ② 위반 → ⚠ "이미 등록된 기관입니다 — 기존 계정 해지 후에만 새 가입자를 초대할 수 있습니다". 어느 쪽이든 [초대 발송] 비활성. 다시 입력하면 기존 경고를 지운다.
연동 값이 정상이면 [초대 발송] 활성 조건을 다시 본다.
저장 ORG.name으로 저장한다. 커스터디에 등록된 법인명과 같게 입력한다(집행 명세 Excel의 법인명 열이 커스터디 품의 서식과 어긋나지 않도록). 기관 식별자는 별도로 채번하지 않고 customerNo(항목 3)를 쓴다(종전 ORG-NNNN 자동 채번 폐기 · 2026-09-07 결정).

customerNo 입력필수
입력 가능 항상 가능하다. 플레이스홀더는 "customerNo (L-XXXXXX-XXXX)"다. 값은 커스터디가 오프라인 온보딩(CDD)을 마친 뒤 이메일 등으로 알려 준 고객 식별번호를 그대로 옮긴다.
허용 문자 L- + 영숫자 6자 + - + 영숫자 4자(총 13자). 대문자로 정규화하고 공백은 지운다.
검증 ① 형식 일치 ② 다른 기관에 등록되지 않은 값일 것. ①은 포커스 아웃 시 클라이언트가, ②는 [초대 발송] 클릭 시 서버가 본다.
실패 처리 ① 위반 → 빨간 테두리 + ⚠ "customerNo 형식이 올바르지 않습니다 (L-XXXXXX-XXXX)". ② 위반 → ⚠ "이미 등록된 customerNo입니다". 어느 쪽이든 [초대 발송] 비활성.
연동 값이 정상이면 [초대 발송] 활성 조건을 다시 본다.
저장 ORG.customer_no로 저장하고 이 값이 기관 식별자다(내부 채번 ORG-NNNN 폐기 · 2026-09-07 결정). 목록·집행 명세 Excel·CSV·감사로그가 같은 값을 쓴다. 등록 뒤에는 이 화면에서 고치지 않는다 — 오기·변경은 커스터디에 이메일로 요청하고 커스터디가 처리한다.

수탁 지갑 주소 입력필수
입력 가능 항상 가능하다. 플레이스홀더는 "수탁 지갑 주소 (0x…)"다. 커스터디가 이 법인에 만들어 준 수탁 지갑 주소를 옮긴다 — 법인 1사 · 체인 1개당 1지갑이고 지금은 Ethereum 단일이라 칸 1개(ETH·USDC·USDT 공용). 체인이 늘면 체인별 칸을 추가한다.

[초대 발송] 버튼필수
노출 항상 보인다(primary).
클릭 가능 기관명·이메일·customerNo·수탁 지갑 주소 4칸이 모두 정상이고 인라인 오류가 0이며 발송 중이 아닐 때만 활성이다. 목업은 빈칸이라 비활성이다.

ORG를 만들고(식별자 = customerNo · 수탁 지갑 주소 저장) USER를 만든 뒤(계정 상태 '초대 발송됨') 초대 이메일(ONB-00)을 72시간·1회 유효로 보낸다. 생성과 발송은 원자적으로 처리하고 발송이 실패하면 생성을 되돌린다. 목록 최상단에 행을 추가하고 폼을 비우며 토스트 "초대 이메일을 발송했습니다 — {이메일 마스킹} · 72시간 유효"를 띄운다. 화면 이동은 없다. 이후 가입자는 ONB-01~03에서 계정을 활성화하고 AUTH-01로 들어온다. 기관 상태 초기값은 '활성'이다 — customerNo가 발급됐다는 것은 커스터디 오프라인 CDD가 끝났다는 뜻이다(2026-09-07 결정 · 종전 '심사중(EDD)' 초기값과 [확인필요] 종결). 이후 변동은 커스터디 조회값으로 반영된다(항목 7 · 이 콘솔에서 바꾸지 않는다). 기관당 1계정이라 기존 가입자가 있으면 해지 후에만 초대할 수 있다.

  01 신규 커스터디에 등록은 됐으나 아직 거래를 열어주지 않은 상태(노랑) · 02 활성 고객확인이 끝나 거래할 수 있는 정상 상태(초록) · 03 휴면 오래 쓰지 않아 재워둔 상태(노랑) · 04 거래중지 문제가 있어 커스터디가 거래를 멈춰 놓은 상태(노랑) · 05 거래해지 계약이 끝나 관계가 종료된 상태(회색) · 06 거래거절 고객확인을 통과하지 못해 거절된 상태(노랑).
  02 활성만 거래할 수 있다. 나머지 5종은 의미를 나누지 않고 전부 같게 처리한다 — 고객 콘솔에서 조회는 되고, 요청·게시·신청·수락 버튼은 비활성이며, 화면 위에 안내 배너가 뜬다. 배너 문구는 6종 모두 같다(어떤 상태인지 고객에게 알리지 않는다).
  종전 5종(심사중(EDD) · 활성 · 일시제한 · 동결 · 해지)은 2026-09-07에 폐기했다. 새 체계에서 심사중(EDD)의 자리는 01 신규와 06 거래거절이 대신한다. DB는 ORG.status에 코드를, ORG.status_checked_at에 조회 성공 시각을 넣고 ORG.kyc_status 컬럼은 삭제한다(01·06과 중복).
· 커스터디 연동 방식: 기관 상태는 조회 API로만 읽는다. 커스터디가 우리에게 먼저 알려주는 변경 통지(웹훅)는 없고, 관문마다 다시 묻는다. 거래 위험도 통지로 받지 않는다 — 커스터디가 집행 전 심사에서 문제를 발견하면 서명하지 않고 처리함(ADM-02) ② 행의 [AML 이슈 미집행]을 누른다.

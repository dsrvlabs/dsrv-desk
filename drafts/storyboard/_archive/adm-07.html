자동검증 결과 첨부·에스컬레이션필수
· [공통 포맷 2026-09-01] 선택 건 상단에 '교환거래 요청 내역'을 고객 화면(EXC-03·04 / BRK-03·04·05)과 동일 필드·순서로 표시: 요청번호 → 교환쌍·방향 → 보내는 수량 → 받는 수량 → 비율 → 요청 일시
· 한도(건별 1억)·화이트리스트·KYT·BLF·트래블룰 결과를 건별 첨부
· 주의·불량 = 자동 거절이 아니라 수동검증 에스컬레이션 — 자동 확정·자동 거절 모두 없음
· AML 심사 상세는 고객 화면 미노출(STR 누설 금지)
근거: 자동검증 1차 필터 [09 §0 line 70·F-4] · STR 누설 금지 [L1 §4 [원문대조필요]]
3
승인·보류·거절 (직무분리)필수
· DSRV 단일 승인 — 단, 본인 기안 건 자기승인 차단(기안↔승인 분리)
· 고액·신규주소 건은 시간지연 승인(지연발효 경과 후 집행)
· 거절·보류 시 사유 필수 입력, 고객에게는 일반화된 사유만 통지
근거: 직무분리 [ISMS 2.2.2·F-4] · 지연발효 [F-3] · 예외케이스 E3·E4·E7
4
처리 이력·감사추적필수
· 처리자·시각·결과·사유 기록 — 위변조 방지·보존(거래 15년/AML 5년)
· 반려·차단 건 중 AML 사유는 STR 파이프라인(ADM-02) 연계
근거: 감사 로그 [L6 §9 · ISMS 2.9]
큐 유입 경로
· 나목: EXC-03 (비율 수락 완료 건 — 고객사 승인 단계 없음, 2026-09-01)
· 마목: BRK-04 (게시자 수락 완료 건 — 신청 시 신청자 측·수락 시 게시자 측 각 2인 승인)
· 출금/이전: 서면 접수 건 — 고객 온라인 화면 없음(커스터디 서면 요청 절차, 2026-09-01)
· 자동검증 주의·불량 → 이 큐로 에스컬레이션
고객 화면과의 분리
· 고객(EXC-03)에게는 "승인 심사 중" 상태와 예상 소요만
· 한도·KYT·BLF·트래블룰 상세는 이 화면에서만 표시(2026-08-31 표시 분리 결정)
· 거절 통지는 일반화된 사유 — 구체적 AML 심사 내용 노출 금지
판단 원칙 (방어)
· 자동검증은 1차 필터 — 자동 체결·자동 승인·자동 거절 없음, 최종 판단은 사람
· "자동체결 거래소 아님" 소명의 핵심 증적 화면
· [확인필요 G4] DSRV 내부 직무분리 최소선(기안↔승인 2인 운영 방식)
비고
· DSRV 내부 관리자 화면(고객사 노출 없음). 관리자 메뉴 '요청·정책' 탭의 요청(심사 큐) — 정책은 ADM-03.
· [정정 2026-09-01] 기존 EXC-03 비고의 "관리자 콘솔 심사 큐(별도 승인 큐 화면 신규 개발 없음)"를 정정 — 심사 상세를 고객 화면에서 제거(2026-08-31)한 이상 관리자 측 심사 화면은 필요하므로 ADM-07로 명시화. ADM-02(시장감시)와 분리해 감시와 승인을 별도 화면으로 유지.
· [방어 핵심] 자동검증(한도·화이트리스트·KYT·BLF·트래블룰)은 1차 필터일 뿐, 승인·보류·거절은 전부 사람의 판단 — "자동체결·자동심사 아님" 소명. 본인 기안 자기승인 차단으로 직무분리 담보.
· [공통 포맷 2026-09-01] 선택 건의 거래 내역 표시는 고객 화면과 동일한 '교환거래 요청 내역' 포맷·필드 순서를 그대로 사용 — 심사자가 고객 화면과 같은 순서로 대조 가능.
· 예외케이스 귀속: E3(자동검증 차단)·E4(maker-checker 반려)·E7(트래블룰 보류) — 처리 결과는 고객 화면(EXC-03·BRK-04)에 상태로만 반영.
· 연결: 유입 EXC-03 · BRK-04 / 정책값 ADM-03 / AML 연계 ADM-02 / 이력 ADM-04

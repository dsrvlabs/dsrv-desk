# 화면기획 컴포넌트 설명 템플릿

스토리보드 항목설명(`itm-desc`)과 화면 이동·인터랙션(`nav-row`)을 쓰는 순서. 2026-09-02 사용자 확정.
대상 = 고객·어드민 화면의 **입력창** · **버튼**. 표시 전용 요소는 이 템플릿 밖(보이는 것·상태만 서술).

**원칙**
- `itm-desc` = 규칙(정적). `nav-row` = 이벤트 → 결과(동적). 같은 내용을 양쪽에 쓰지 않는다.
- '진입 · 전역 이동'(`nav-global`)의 `nav-note`는 **지우는 자리가 아니다**. 정본 3종(AUTH-01 · DASH-01 · ADM-02)에는 정본 표시 + 진입 조건, 나머지 화면에는 "○○ 셸 정본(ID)과 동일" 1줄 + 그 화면의 차이(현재 탭 재클릭 · 입력 중 값 파기 · 진입 경로 · 갱신 방식)를 쓴다. 2026-09-02 정본화 결정.
- 라벨은 굵게(`<strong>라벨</strong>`), 라벨 뒤 한 칸 띄고 서술. 한 줄 한 사실.
- 정책값은 **매번 현재값을 병기**한다: `{정책값 1,500,000원 상당}` · `{정책값 5회}` · `{정책값 72시간}`. 중괄호 안 `정책값` 토큰은 유지(검색용).
- 근거는 마지막 줄 `.basis`. 규제 근거 없는 UX 결정은 "09 §0 결정(날짜)" 또는 "공통 UI 규격"으로 적는다.
- 미확정은 `[확인필요: 무엇]`, 시안 없는 요소는 `[디자인 요청]`.

## 1. 입력창 (input · textarea · OTP 칸 · 검색창)

| # | 라벨 | 반드시 답할 질문 | 해당 없을 때 |
|---|---|---|---|
| 1 | **입력 가능** | 항상 가능한가? 비활성 조건은?(타 값·상태가 이 창을 막는 경우 포함) 진입 시 초기값(빈칸 · placeholder · 기본값)은? | **"항상 가능하다."로 명시** |
| 2 | **허용 문자** | 받는 문자 집합 · 길이/자릿수 상한 · 초과·비허용 입력은 **무시 vs 거부** · 자동 포맷(천 단위 쉼표 · 마스킹 · 대소문자) | 줄 생략 |
| 3 | **검증** | 판정 규칙(①②③ 번호) · **시점**(키 입력마다 / 포커스 아웃 / 제출 시) · **주체**(클라이언트 / 서버 재검증) | 줄 생략 |
| 4 | **실패 처리** | 규칙별 → 표시(인라인 ⚠ 문구 **원문** · 테두리) + 부수 효과(어떤 버튼 비활성) · 동시 위반 시 우선순위 | 줄 생략 |
| 5 | **연동** | **이 값이 바꾸는 것** — 타 필드 재계산 · 옵션 제한 · 표시 갱신. (반대 방향 = 타 값이 이 창을 막는 것은 1번에) | **"없음"으로 명시** |
| 6 | **저장** (선택) | 저장·전송 형식 — 해시, 절사 자릿수, 단위, 서버 전송 값 | 줄 생략 |
| — | 근거 | `.basis` | 필수 |

1·5를 비우지 않는 이유: 빈 줄이면 "빠뜨린 것"인지 "없는 것"인지 개발자가 구분할 수 없다. 2~4는 없으면 컴포넌트 성격상 자명하므로 생략.

### nav-row 매핑 (요소 / 트리거 / 결과)

| 행 | 요소 | 트리거 | 결과 |
|---|---|---|---|
| 정상 1행 | `{필드} — 정상 입력` | 검증 시점(3번) | 경고 제거 · {연동 대상} 갱신 · [{버튼}] 활성 조건 ○ 해소 |
| 실패 n행 | `{필드} — 규칙 ③ 위반` | 검증 시점 | ⚠ "{문구}" · [{버튼}] 비활성 |
| 비활성 m행 | `{필드} (비활성)` | 1번 조건 | 무반응 · 인라인 "{안내}" 또는 배너가 사유 |

행 수 = 1 + (4번 상태 수) + (1번 비활성 조건 수). desc의 규칙 번호와 nav-row가 1:1이어야 한다.

### 예시 — EXC-01 항목 3 「보내는 수량 입력」

```
입력 가능  보내는·받는 자산이 모두 선택된 뒤에만 가능하다. 미선택이면 비활성이고 클릭 시
          "자산을 먼저 선택해 주세요"를 띄운다. 교환 가능 풀이 0이면 비활성 + "현재 교환 불가".
          초기값 빈칸, placeholder "0".
허용 문자  숫자·소수점만. 소수 자릿수 상한 = 보내는 자산 기준(ETH 4 / USDC·USDT 2), 초과분은
          입력 시점에 무시한다. 천 단위 쉼표를 자동 삽입한다.
검증      키 입력마다 클라이언트가 판정한다. ① 0 초과 ② ≤ 1회 한도 {정책값 1,500,000원 상당}의
          해당 자산 환산 수량 ③ ≤ 현재 교환 가능 풀. [거래 요청] 클릭 시 서버가 ②③을 다시 본다.
실패 처리  ② 위반 → 빨간 테두리 + ⚠ "1회 최대 교환 한도(1,500,000원 상당)를 초과했습니다 — 수량을
          줄여 다시 입력해 주세요". ③ 위반 → ⚠ "현재 교환 가능 풀을 초과해 요청할 수 없습니다 —
          수량을 줄여 다시 입력해 주세요". ②③ 동시면 ②만. 어느 쪽이든 [거래 요청] 비활성.
연동      값이 바뀔 때마다 필드 아래 KRW 환산액(ADM-03 시세 소스)과 항목 4의 예상 받는 수량을
          다시 계산한다.
저장      받는 자산 자릿수로 절사한 값을 전송한다.
근거      09 §0 건별 한도·표기 자릿수(2026-09-02) · notation 입력 자릿수
```

nav-row: 정상 1 · 실패 2(②·③) · 비활성 2(자산 미선택 · 풀 0) = 5행.

## 2. 버튼 (primary · ghost · 링크 버튼 · 행 클릭 · **드롭다운**)

드롭다운(▾)은 클릭해서 값을 고르는 조작이므로 이 템플릿을 쓴다(입력창 아님 — '허용 문자' 자리에 옵션을 넣지 않는다). 옵션 목록은 **액션** 앞에 `**옵션**` 줄로 나열하고, 액션에는 선택 시 결과(칩 갱신 · 닫힘 · dirty 표시 · 연동)를 쓴다. 바깥 클릭/ESC 닫힘은 공통 UI 규격이라 생략.

| # | 라벨 | 반드시 답할 질문 | 해당 없을 때 |
|---|---|---|---|
| 1 | **노출** | 이 버튼이 화면에 **나타나는** 조건. 조건부면 그 조건. | **"항상 보인다."로 명시** |
| 2 | **클릭 가능** | 노출된 상태에서 활성/비활성이 갈리는 기준(번호 ①②③). Enter 키 동작 여부. 처리 중 비활성(중복 클릭 차단) 여부. | 줄 생략(= 항상 활성) |
| 3 | **확인 사항** | 클릭 직후 검증할 것 — 서버 재검증(잔고·한도·풀·경쟁 상태) · 확인 다이얼로그 **유무와 문구** | **"없다. 확인 다이얼로그를 띄우지 않는다."로 명시** |
| 4 | **액션** | 확인 통과 후 순서대로 — 저장 · 상태 전이 · 채번 · 감사로그 · 통지 · 화면 이동(목적지 화면 ID) | 필수 |
| — | 근거 | `.basis` | 필수 |

1(노출)과 2(클릭 가능)를 반드시 구분한다 — 섞으면 조건부 노출을 비활성으로 잘못 구현한다.
3(확인 사항)을 비우지 않는 이유: "다이얼로그 없음"은 해당 없음이 아니라 개발자가 임의로 확인창을 넣지 못하게 하는 정보다. 생략 가능한 줄은 2(= 항상 활성)만.

### nav-row 매핑 (기존 3행 규격 유지)

| 행 | 요소 | 트리거 | 결과 |
|---|---|---|---|
| 활성 조건 | `[{버튼}] — 활성 조건` | 2번 조건 열거 "다음이 모두 아님: ①…②…" | 하나라도 해당 → 회색 비활성(공통 UI 규격) · 사유는 인라인 경고로 이미 노출 |
| 클릭(활성) | `[{버튼}] — 클릭(활성)` | 라벨 "처리 중…"·비활성 → 3번 확인 → 4번 액션 | **목적지 화면(ID)** · 진입 상태 |
| 실패 | `[{버튼}] — 실패` | 3번 확인 실패 종류 나열 | 화면 잔류 · 종류별 표시(배너/인라인) · 라벨 복귀 · 입력값 유지 여부 |

### 예시 — EXC-01 항목 6 「[거래 요청]」

```
노출      항상 보인다.
클릭 가능  다음이 모두 아닐 때 활성: ① 보내는·받는 자산 미선택 ② 수량 빈칸·0 ③ 한도 초과 경고 노출 중
          ④ 풀 초과 경고 노출 중 ⑤ 풀 0 ⑥ KYC 예외 배너 노출 중 ⑦ 풀·비율 조회 실패 ⑧ 처리 중.
          Enter 키는 처리하지 않는다.
확인 사항  서버가 요청 시점 풀과 한도를 다시 검증한다. 확인 다이얼로그는 없다(요청 접수 단계 · 구속력 없음).
액션      요청번호 EXC-YYYYMMDD-NNNN 채번 → 요청 시점 외부지표 + 스프레드 {정책값 0.10%}로 비율 자동 산정
          → 비율 확인·수락(EXC-02) 진입. 자동인 것은 산정까지 — 체결은 수락·승인·수동 집행으로 분리.
근거      F-4 · 09 §0 나목 견적 산정(2026-09-02)
```

## 3. 적용 체크리스트 (화면 하나 끝낼 때)

- [ ] 입력창마다 1·5 라벨이 있다(없으면 "항상 가능하다" / "없음").
- [ ] 버튼마다 1·3 라벨이 있다(없으면 "항상 보인다" / "없다. 확인 다이얼로그를 띄우지 않는다").
- [ ] 드롭다운은 버튼 템플릿 + `옵션` 줄로 썼다(입력창 템플릿 아님).
- [ ] 정책값에 현재값이 병기돼 있다(`{정책값 …}`). 값 없는 `{정책값}` 단독 표기가 남아 있지 않다.
- [ ] desc의 규칙 번호(①②③)와 nav-row 실패 행이 1:1이다.
- [ ] 같은 문장이 desc와 nav-row 양쪽에 없다.
- [ ] 오류 문구는 원문 인용(따옴표)이고 공통 UI 규격 문구 ①~와 충돌하지 않는다.
- [ ] "렌더한다" 없음 → "보인다 / 보이지 않는다". 본문 검정, `[확인필요]`·`.basis`만 회색.

상세내용
1복구 코드 규격
형식 단일 코드 1개, 영숫자 24자(4자×6그룹, 표시 시 " - " 구분), 1회용, 해시 저장. 사용·실패를 감사로그에 남긴다.
발급 계정 활성화 3/3 복구 코드 저장(ONB-03)에서 1회 표시·복사. 재발급은 2차 인증 재설정(DASH-03) 완료 시(이전 코드 폐기).
입력 UI 6칸이 아니라 텍스트 필드 1개를 쓴다(항목 1). 구분자 " - "는 자동 삽입하지 않고 입력값에서 무시만 한다. [디자인 요청: 입력 중 4자 단위 구분 표시 여부]
2인증 성공 후 처리
세션 6자리 코드 인증과 같은 세션을 만든다(유휴 {정책값 15분} · 최대 {정책값 8시간} · 계정당 1세션). 인증 앱 등록은 그대로 유지한다.
권고 배너 대시보드(DASH-01) 상단에 "복구 코드로 로그인했습니다. 인증 앱을 다시 등록하려면 2차 인증 재설정으로 이동하세요" 배너를 이 세션 동안 띄운다(닫기 없음).
전면 분실 복구 코드까지 없으면 관리자 본인확인 후 초대 재발송으로 처리한다(화면 밖 운영 절차).
[확인필요] 2차 시안은 "확인 후 2FA가 초기화됩니다. 다시 로그인하고 2FA를 설정해야 합니다"로 되어 있다(인증 즉시 2FA 해제 → 재로그인 → 재설정). 기획은 세션 생성 + 재설정 권고 배너를 유지했다. 채택하면 이 항목·DASH-01 배너·DASH-03 흐름을 함께 바꾼다.
3사전 인증 · 되돌아가기
상태 AUTH-02와 같은 사전 인증 상태({정책값 120초})를 쓴다. AUTH-02 ↔ AUTH-03 이동으로 연장·초기화하지 않는다.
카운터 통합 카운터(비밀번호·인증 코드·복구 코드 실패 합산)를 두 화면이 공유한다. [확인필요: 합산 카운터 vs 단계별 개별 카운터]
이전으로 이 화면에서 로그인(AUTH-01) 1단계로 바로 가는 링크는 두지 않는다(2026-09-02 확정 · 보조 링크 없음).

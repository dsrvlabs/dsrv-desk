1왜 이메일 초대인가
신원 확인 본인 이메일 수신과 링크 접근이 1차 신원 확인 축이다.
책임 추적 계정별 개별 초대로 공용 계정을 막고 활동 로그의 책임자를 특정한다.
이메일 변경 수신 주소는 ADM-03 입력값으로 고정하고 콘솔에 변경 화면을 두지 않는다. 변경은 해지 후 재초대다.
2본문이 담는 것
비밀번호 메일에 담지 않으므로 서버와 이메일에 평문으로 존재한 적이 없다.
1조직 1계정 계정과 실제 사용자를 1:1로 묶어 행위 책임자를 특정한다. 조직 내 추가 가입 경로는 없다.
내용 제한 심사와 AML 내용은 넣지 않는다.
3토큰 케이스 → 표시 위치
표시 위치 토큰 오류는 초대 링크 오류(ONB-04) 한 화면에서만 보여준다. ONB-01에 배너 변형을 두지 않는다.
통합 만료(발송 + 72시간 경과)와 이미 사용됨(활성화 완료로 소멸)을 구분하지 않고 같은 문구를 쓴다 — 토큰 상태를 알려주지 않는다.
재발급 ADM-03 초대 재발송으로만 한다(새 토큰 · 이전 토큰 즉시 무효).
재개 활성화 미완료 상태의 재클릭은 재개로 처리해 진행 중 화면으로 라우팅하므로 오류 화면에 오지 않는다.

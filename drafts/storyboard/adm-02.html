알람·워닝 처리함필수
· 사람이 처리해야 할 일만 한 처리함에 통합 — 조회성 화면 없음
· 유입: 나목 교환 승인(EXC-03) · 마목 확정 확인(BRK-04) · 출금/이전 서면 접수 · 입금 예외 B1~B5(격리·동결) · 이상거래(자전·통정·위장게시) · 월렛/키 접근 알람 · 제재·다크코인 적중 · KYC 재이행 도래·미응답 · 계정 잠금(AUTH-01) · 3면 대사 불일치(X3)
· 유형별 행에서 인라인 처리 — 별도 상세 화면 없음, 선택 건 상세는 행 확장으로 '교환거래 요청 내역' 공통 폼 표시
· 자동검증은 1차 필터 — 자동 체결·자동 승인·자동 거절 없음, 최종 판단은 사람 · 본인 기안 자기승인 차단 · 고액·신규주소 건 지연발효 · 보류·거절 사유 필수(고객 통지는 일반화된 사유만)
· toast(순간) + 처리함(누적·상태관리) 두 축 — 외부 메신저 연동 없음
근거: 승인 대기함 [32 §6 APR-01] · 자동검증 1차 필터 [09 §0 line 70·F-4] · ISMS 2.11.3(이상행위 모니터링)·2.2.2(직무분리) · 예외 B1·B2·E3·E4·E7·H3·X3
화면 이동 · 인터랙션
처리함 행클릭 — 행 확장(별도 상세 화면 없음)화면 내 — '교환거래 요청 내역' 공통 폼으로 선택 건 상세 표시
행 내 처리 버튼
(승인 / 보류 / 거절 / 소명 인정 / STR·동결 / 무혐의 종결 / 해제 등)클릭 — 인라인 처리 · 보류·거절 사유 입력 필수 · 본인 기안 자기승인 차단 · 고액·신규주소 건 지연발효화면 내 상태 전이(상태 전이 문서 참조) · 출금 건 승인 → 집행 대기 행으로 이동 · 처리 결과는 고객 화면에 상태로만 반영(STR 누설 금지) · 전 처리 감사기록
2
승인 → 집행 분리 (멀티시그 화면 없음)필수
· 콜드월렛 2인 멀티시그 서명·집행은 화면 밖 커스터디 운영절차로 분리 — 지갑 운영 화면 없음
· 집행 대기 건은 집행 명세(Excel) 다운로드 제공 — 출금 지갑·수신 주소·자산·수량 등 콜드에서 수행할 작업을 명세서 형태로 전달
· 콜드 집행 후 담당자가 txhash 입력 → 온체인 조회로 명세와 대사(주소·자산·수량 일치) — 일치 시에만 완료 확정, 불일치 시 처리함 워닝
· 명세 다운로드·txhash 입력·완료 처리 모두 감사 기록(누가·언제)
· 콜드→핫 보충·스윕 등 지갑 이동도 동일 경로 — 온라인 집행 버튼 없음
근거: 콜드월렛 중심 보관 [L4 §26] · 멀티시그 [ISMS 2.7.2] · 예외 B6·F6·H4
화면 이동 · 인터랙션
[집행 명세 다운로드 (Excel)]클릭 — 콜드에서 수행할 작업 명세 전달파일 다운로드 · 화면 이동 없음 · 감사기록
txhash 입력 → [완료 처리]온체인 조회로 명세와 대사(주소·자산·수량 일치)일치 → 완료 확정·잔고 반영 / 불일치·미확인 → 완료 불가, 처리함 워닝 회송
3
데이터 다운로드 (CSV 6종)필수
· 조회성 데이터는 화면 표 없이 CSV 다운로드 버튼만 6종: 기관-가입자 목록 · 거래 요청 목록 · 통합 거래 목록 · 구분회계 집계 · 3면 대사 · 열람 기록 — 분석은 CSV로 오프라인 수행
· 실명·연락처 등 개인식별정보는 CSV에서도 마스킹 · 개인키·passphrase·시드는 어디에도 기록하지 않음
· 모든 다운로드는 열람 기록에 감사 기록(누가·무엇·언제) — 그 열람 기록도 CSV로 다운로드
· 3면 대사 불일치 발생 시 처리함 워닝 + 해당 지갑 출금 자동 동결
· CSV 6종의 컬럼 정의·DB 스키마 매핑은 하단 부록 표 참조
근거: 구분회계 [V11] · 기록 보존 [L6 §9] · ISMS 2.9.4(로그·접속기록)·2.6.3(표시 최소화)
화면 이동 · 인터랙션
CSV 다운로드 6종클릭파일 다운로드 · 화면 이동 없음 · 열람 기록(⑥)에 감사기록

근거: ISMS 2.6 · PAM

1구 화면 귀속 이관

· 시장감시·알람함(구 ADM-02) → 이상거래·월렛/키 워닝 행
· 격리·동결(구 ADM-08) → 입금 예외 행
· 계정 잠금·재이행(구 ADM-06) → 잠금·KYC 행 (초대·상태 전이는 설정 ADM-03)
· STR 검토 처리 후 작성·보고는 별도 AML 시스템 — 작성자↔보고책임자 분리(자기검증 방지), FIU 보고·5년 보존
· [확인필요] 24×365 상시 확인 주체·당직 운영 방식 — toast+처리함은 상시 확인 주체 전제에서 성립
2집행 대기 상태 흐름
승인(처리함) → 집행 대기 → 집행 명세(Excel) 다운로드 → 콜드 2인 서명·집행(커스터디 절차) → txhash 입력 → 온체인 대사 일치 → 완료 반영
· txhash 불일치·미확인 시 완료 처리 불가 — 처리함 워닝으로 회송
· 서명 시스템 장애 시 BCP/DR — 정산 일시 중지 공지(예외 F6)
· 긴급 시 승인을 멈추면 집행도 멈춤 — 별도 긴급정지 버튼 없음(ISMS 2.11.1)

케이스분기 — 거래·계정 상태가 갈리는 경우와 화면 반영

한 건이 갈라지는 경우 · 트리거 · 고객 목록/상세·어드민 반영 · 카드 집계 (개발 이관용) · v0.4 2026-09-02 — 종전 "상태 전이(처리함)" 문서를 케이스분기로 확장: 나목·마목 고객 케이스 표 신설, DASH-01 카드·ADM-02 KPI 집계 정의 신설 · 어드민 유형 T1~T8·X3 전이는 §4에 유지 · 나목 고객 "보류" 라벨 폐지(진행 중 → 완료/거절만) 반영
이 문서를 읽는 법

케이스분기 = 거래 한 건(교환 요청·게시·신청·출금·입금) 또는 계정 하나가 시작해서 끝날 때까지 갈라질 수 있는 경우를 전부 나열한 것이다. 경우마다 ① 무엇이 상태를 바꾸는지(트리거), ② 그 결과 고객 화면과 어드민 화면에 각각 무엇이 보이는지, ③ 대시보드·KPI 카드 어디에 세어지는지를 한 행에 적었다.

상태는 세 축으로 나뉜다. 고객 상태(DASH-01 칩 라벨 — 내부 심사 단계를 감춘 고객용 이름) · 어드민 업무 상태(ADM-02 처리함 '상태' 컬럼 — 승인 대기·격리 중 등 실제 업무) · 처리함 공통 상태 5종(OPEN·ESCALATED·IN_PROGRESS·HOLD·RESOLVED — KPI 집계용). 같은 순간에 세 축의 값이 서로 다를 수 있고, 그 대응을 §1~§3 표가 정의한다. 코드 후보(영문)는 CSV·DB enum 초안이며 확정 전이다결정필요 ⑨.

화면 박스(EXC-02 등)를 클릭하면 해당 화면기획으로 이동한다. 어드민 유형(T1~T8·X3)의 상세 전이는 §4에 그대로 두었다.

§4

어드민 처리함 유형별 전이 (T1~T8 · X3)

종전 "상태 전이(처리함)" 본문 — 그대로 유지
용어
나목 교환
고객이 DSRV를 상대방으로 하는 ETH·USDC·USDT 교환 (예: ETH↔USDC, USDC↔USDT · 2026-09-02 ETH 편입). 가상자산사업자 신고 업종 구분에서 온 이름으로, 이 문서에서는 "DSRV와의 직접 교환"으로 읽으면 된다.
마목 중개
고객 간 교환을 DSRV가 게시판 방식으로 중개하는 것. 게시자가 신청을 수락하는 순간 거래가 확정되고 법적 구속력이 생긴다. 게시당 신청은 동시에 1건만 받는다(신청 1건 접수 = 게시 '협의중' · 추가 신청 차단). 확정 전까지 게시자는 게시를 회수할 수 있다(BRK-06 · 2026-09-02). 중개 수수료는 거래액의 1% 고정, 양측 각자 부담(기준 = 각자 보내는 자산 수량).
KYT
트랜잭션의 자금 출처·경로 위험도를 자동 분석하는 검사 (Know Your Transaction).
BLF
제재 대상·블랙리스트에 오른 지갑 주소인지 대조하는 필터.
STR
의심거래보고. 자금세탁이 의심되는 거래를 금융당국(FIU)에 보고하는 절차. 보고 대상 고객이 보고 사실을 알게 해서는 안 된다(누설 금지).
에스컬레이션
자동검증에서 위험등급 '주의' 이상이 잡힌 건. 일반 대기 건과 구분해 우선 검토한다.
지연발효
새 출금 주소를 등록해도 일정 시간이 지나야 실제 출금이 가능해지는 보호장치. 계정 탈취 시 즉시 출금 피해를 막는다.
격리 지갑
위험 신호가 있는 입금을 고객 잔고에 반영하지 않고 따로 보관하는 지갑.
3면 대사
내부 장부 · 블록체인 실제 잔고 · 콜드월렛 기록, 세 곳의 수치가 서로 일치하는지 맞춰보는 정기 점검.
트래블룰
가상자산을 이전할 때 송신인·수신인 정보를 함께 전달해야 하는 규제 요건.
상태 모델 — 2계층 분리 아이템 공통 상태 + 대상 업무 상태

8가지 유형은 대상 업무가 서로 달라(교환 승인, 입금 격리, 계정 잠금…) 상태 이름을 하나로 통일하면 실제 업무가 안 보인다. 그래서 두 층으로 나눈다.

① 아이템 공통 상태 (5종) — 유형과 무관하게 "아직 안 봤나 / 처리 중인가 / 끝났나"를 집계하는 공통 축. ADM-02 상단 KPI(처리 대기 N건 등)가 이 축을 센다(§3 대응표).
② 업무 상태 — 유형별 실제 업무 상태(승인 대기, 격리 중, 잠금 등). 처리함 '상태' 컬럼에 표시되는 값. 아래 유형별 패널과 총목록이 이 축이다.

아이템 공통 (5종) OPEN 미처리→ ESCALATED 에스컬레이션→ IN_PROGRESS 처리중→ HOLD 보류→ RESOLVED 종결 + 결과코드
· 자동검증 등급이 '주의' 이상이면 처음부터 ESCALATED로 생성된다 · RESOLVED에는 결과코드가 붙는다: 승인 / 거절 / 소명 인정 / 동결 / STR 이관 / 무혐의 / 조치완료 / 해제 / 제한 적용 / 이전 중지 / 차단 / 자동 종결(T7)
· 누가 상태를 바꾸는가 — 시스템(자동): 아이템 생성 전부 · 지연발효 타이머 만료(T3) · 온체인 확정 반영(T1·T3) · 재이행 완료 자동 종결(T7) · 격리/동결/잠금의 개시 / 사람(관리자): 종결로 가는 판단 전부 — 자동 체결·자동 승인·자동 거절 없음 · 본인 기안 자기승인 차단 · 보류/거절 사유 필수 · 모든 전이 감사로그 기록
T1나목 교환 승인 대상: 교환 요청
고객이 DSRV와의 교환 비율을 수락하면(EXC-02[수락] — 클릭 즉시 확정, 확인 다이얼로그 없음 · 참고 비율(EXC-01)·확정 비율(EXC-02) 2회 고지로 대체, 2026-09-02 결정) 요청이 확정되고, 실제 집행 전에 관리자 승인을 거친다. 그 승인 건이 여기 쌓인다. 모든 요청이 예외 없이 유입되며(자동 통과 없음), 시스템이 건별 한도·잔고·BLF·KYT 자동검증 결과를 붙여서 생성한다. 생성 시점 — EXC-02비율 수락 즉시
승인 대기 승인(사람)→ 집행 대기 서명·집행(오프라인)→ 완료
승인 대기 보류(사유)→ 보류 재검토→ 복귀 / 거절(사유)→ 거절
· 위험등급 '주의' 이상이면 에스컬레이션 상태로 생성 · 고객 화면에는 승인 대기~집행 대기를 'DSRV 거래 진행중' 하나로만 표시해 내부 단계를 노출하지 않고(EXC-03), 보류 중에도 고객에게는 '진행 중'으로만 보인다(고객 화면 보류 라벨 폐지 · 2026-09-02) — EXC-04의 '심사 후 보류' 변형은 후속 정리 대상 · AML 사유로 거절한 건은 STR 검토로 연계
T2마목 확정 확인 대상: 확정 거래
중개 거래는 게시자가 신청을 수락하는 순간 이미 확정되어 법적 구속력이 생긴다. 그래서 이 아이템은 거래 성립을 승인하는 것이 아니라, 확정된 거래의 자산 이전(정산)을 진행해도 되는지 확인하는 절차다. 생성 시점 — BRK-04게시자 수락(=확정 · 확인 다이얼로그 후 실행) 즉시 — 고객 도메인의 게시 상태 협의중 → 확정 전이와 동시(아래 '마목 게시 상태' 패널)
확인 대기 승인(사람)→ 이전 진행 정산 배치→ 완료
확인 대기 보류(사유)→ 보류 / 거절·차단→ 이전 중지
· 거절은 거래 취소가 아니라 이전 중지 — 이미 확정된 거래를 중지했을 때의 계약상 처리(무산·위약 여부)는 약관·법무 확인 필요결정필요 ① · 트래블룰 정보가 갖춰지지 않은 건은 보류했다가 보완되면 재진행 · 실제 이전은 BRK-05 정산 배치(1영업일 3회)로 실행
T3출금·이전 (서면 접수) 대상: 출금·이전 요청
고객의 출금·이전은 서면으로 신청받아 관리자가 시스템에 등록한다. 처음 쓰는 출금 주소라면 화이트리스트 지연발효 타이머가 자동으로 시작되고, 타이머가 끝나기 전에는 승인할 수 없다. 생성 시점 — 서면 신청 접수(관리자 등록) 즉시
대기 (지연발효 중) 타이머 만료→ 대기 (승인 가능) 승인(사람)→ 집행 대기 서명·집행→ 완료
거절(사유)→ 거절 / 출금 시점 BLF 적중→ 차단
· 타이머 만료는 승인 버튼이 활성화되는 것뿐 — 자동 승인이 아니다 · 출금 실행 시점에 주소를 다시 검사해 제재 리스트에 적중하면 차단하고, STR 검토 아이템(T5 성격)을 새로 생성
T4입금 격리 대상: 입금 트랜잭션
입금을 상시 감시하다가 KYT 고위험 또는 제재·블랙리스트 적중이 감지되면, 해당 입금을 격리 지갑으로 자동 분리하고 고객 잔고에 반영하지 않은 채 아이템을 생성한다. 제재 적중 건은 생성과 동시에 동결 상태로 들어온다. 생성 시점 — 입금 감시 룰 적중 즉시 (격리·잔고 미반영과 동시)
격리 중 소명 요청→ 소명 대기 (HOLD) 소명 인정→ 해제 · 잔고 반영
소명 대기 불인정→ 동결 + STR 검토
· STR 검토 자체는 별도 AML 시스템에서 진행(작성자·보고자 분리) · 제재 적중 건의 법정 통지·보고 절차는 [원문대조필요] · 소명 시한과 시한 초과 시 기본 처리 미정결정필요 ②
T5이상거래 워닝 대상: 거래·게시 패턴
건 하나는 정상처럼 보여도 패턴이 수상한 경우다. 연관 당사자끼리의 거래 매칭, 게시·취소의 반복, 사후 분석에서 발견된 이상 패턴 등이 룰에 걸리면 아이템이 생성된다. 룰 적중은 자동이지만, 의심거래인지 판단은 사람이 한다. 생성 시점 — 이상행위 룰 적중 즉시
미처리 검토→ 검토중 STR 검토→ STR 이관 / 무혐의→ 무혐의 종결
· STR 이관 시 필요하면 해당 기관 계정에 신규 거래 일시제한을 함께 적용(T7 경로) · 고객 화면에는 어떤 표시도 하지 않는다(STR 누설 금지) — 처리 결과는 개별 거래의 상태로만 간접 반영
T6월렛·키 알람 대상: 지갑·키 이벤트
지갑·키 운영의 보안 이벤트다. 콜드월렛에서 인가되지 않은 이체 시도가 감지되거나(High), 핫월렛 보유 비중이 임계값 20%를 넘거나(콜드로 옮기라는 스윕 워닝 — 임계값은 ADM-03정책값), 서명 시스템에 장애가 생기면 아이템이 생성된다. 생성 시점 — 감시 시스템 이벤트 감지 즉시
미확인 확인(사람)→ 확인 조치완료→ 조치완료
· 실제 조치(키 교체·콜드 이관 스윕·비상 대응)는 화면 밖 운영 절차로 수행 — 처리함에는 확인과 조치 결과만 기록
T7KYC 재이행 대상: 기관·가입자 계정
고객확인(KYC)은 위험등급별 주기(고위험 1년·중위험 2년·저위험 3년)로 다시 이행해야 한다. 기한이 지나도록 고객이 응하지 않거나, 실소유자 변경 같은 이벤트로 수시 재이행이 필요해지면 아이템이 생성된다. 생성 시점 — 재이행 기한 초과·미응답 또는 이벤트 트리거 발생 시
일시제한 예정 신규 거래 제한(사람)→ 제한 적용 / 재이행 완료→ 자동 종결
· '제한 적용' = 계정 상태를 활성→일시제한으로 변경(ADM-03상태 기계 — 전 화면 접근 게이팅 G-3의 단일 출처) · 고객이 재이행을 완료하면 자동 종결 — "종결은 사람" 원칙의 유일한 예외로 둔 기획 가정결정필요 ③ · 일시제한→활성 복귀는 사람이 ADM-03에서 수행
T8계정 잠금 대상: 가입자 계정
로그인 5회 실패로 계정이 자동 잠기거나(AUTH-01로그인), 계정 탈취가 의심되는 정황이 감지되면 아이템이 생성된다. 탈취 의심 건은 High 등급으로 들어오고 세션 차단이 병행된다. 생성 시점 — 자동 잠금·탈취 의심 감지 즉시
잠금 본인확인 후 해제→ 해제 · 활성 복귀 / 탈취 의심 판단→ 동결 전환
· 동결로 전환하면 STR 검토 아이템(T5 성격)을 새로 생성 · 계정 상태 전이는 ADM-03 상태 기계를 따름
＋3면 대사 불일치 (X3) 추가 유형 — 현 ADM-02 표에 예시 행 없음
내부 장부·온체인 잔고·콜드월렛 기록을 맞춰보는 대사 배치에서 세 값이 일치하지 않으면 아이템이 생성되고, 동시에 해당 지갑의 출금이 자동 동결된다. 원인이 규명되어 일치가 확인되기 전에는 재개할 수 없다. 생성 시점 — 대사 배치 불일치 감지 즉시 (출금 동결과 동시)

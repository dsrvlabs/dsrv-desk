# 알람·워닝 처리함 — 유형별 트리거·상태값·전이 정의

### 2026-09-01 · v0.1 · ADM-02 처리함 개발 이관용

- 목적: ADM-02 '알람·워닝 처리함'의 **행(아이템)이 언제 생기고, 상태값이 무엇이며, 어떤 트리거로 전이되는지**를 유형별로 정의 → 개발 입력값.
- 근거: 화면기획 v0.5 (adm-02 · adm-03 · exc-03 · brk-04) · 28 예외케이스 · DB스키마 v0.3(참고 — 하단 '스키마 반영 필요' 참조).
- 원칙(전 유형 공통, ADM-02 확정 사항):
  - **자동 체결·자동 승인·자동 거절 없음** — 시스템은 아이템 생성·1차 필터(자동검증)·타이머 전이까지만, 종결은 항상 사람.
  - 본인 기안 자기승인 차단(직무분리) · 보류/거절 시 **사유 입력 필수**(고객 통지는 일반화된 사유만, STR 누설 금지).
  - 모든 상태 전이는 AUDIT_LOG 기록(행위자·시각·사유).

## 1. 상태 모델 — 2계층 구조 (제안)

처리함 아이템의 상태와 대상 객체(거래·계정·지갑)의 상태를 분리한다.

```
[처리함 아이템 상태]  공통 5종 — 처리함 UI의 필터·카운트(KPI '처리 대기' 등)에 사용
  OPEN(미처리) → IN_PROGRESS(처리중) → HOLD(보류) → RESOLVED(종결·결과코드) / ESCALATED(에스컬레이션)

[대상 도메인 상태]   유형별 상이 — 화면 '상태' 컬럼에는 이쪽 라벨을 표출
  예: 교환 요청 '승인 대기', 입금 '격리 중', 계정 '잠금'
```

- 처리함 표의 '상태' 컬럼 = **도메인 상태 라벨** (승인 대기 · 격리 중 · 잠금 …).
- KPI 카드(처리 대기 6 · High 워닝 3)는 **아이템 상태**(OPEN+HOLD 합산 등)로 집계.
- 이렇게 나누는 이유: 유형이 8종+로 이질적이라 상태를 한 enum에 합치면 유형 추가 때마다 enum이 깨짐. 아이템 상태는 고정 5종으로 두고, 도메인 상태는 각 객체의 상태 기계를 따른다.

### 아이템 공통 필드 (생성 시)

| 필드 | 값 |
|---|---|
| 유형 type | 아래 §2의 T1~T8 |
| 대상 target | 도메인 객체 FK (교환 요청·RFQ·입금 tx·계정·지갑·대사 배치) |
| 자동검증·등급 | 정상 / 주의(Mid) / High / 지연발효 중 / — (유형별) |
| 아이템 상태 | OPEN (단, 자동검증 '주의' 이상이면 ESCALATED로 생성) |
| 생성 트리거 | §2 유형별 정의 |

## 2. 유형별 정의 (T1~T8)

### T1. 나목 교환 승인 — 대상: 교환 요청(EXC)

- **생성 트리거**: 고객이 EXC-02에서 비율 수락(기안) → 자동검증(건별 한도·잔고·BLF·KYT) 결과 첨부되어 아이템 생성. 나목 요청은 **전건 유입**(자동 통과 없음).
- **생성 상태**: 자동검증 정상 → `승인 대기` / 주의 이상 → `에스컬레이션`

| 액션(사람) | 전이 | 후속 효과 |
|---|---|---|
| 승인 | 승인 대기 → **집행 대기** | 집행 대기 목록으로 이동(ADM-02 존 2). 콜드 2인 서명·집행은 화면 밖 절차 |
| 보류 | 승인 대기 → 보류 | 사유 필수. 고객 화면(EXC-04) `심사 후 보류` + 일반화 사유 |
| 거절 | 승인 대기 → 거절(종결) | 사유 필수. AML 사유 거절 건은 STR 검토 연계(예외 E3) |
| (시스템) 온체인 확정 | 집행 대기 → 완료 | 상태만 반영(집행 버튼 없음). 고객 화면 `완료` |

- 고객 표출: 승인 대기~집행 대기 구간은 통째로 `DSRV 거래 진행중` 단일 표기(EXC-03) — 내부 단계 미노출.
- 제약: 본인 기안 자기승인 차단.

```
기안(EXC-02 수락) ─▶ 승인 대기 ─승인▶ 집행 대기 ─서명·집행(오프라인)▶ 온체인 확정 ─▶ 완료
                      ├─보류▶ 보류(사유) ─재검토▶ 승인 대기 복귀 or 거절
                      └─거절▶ 거절(종결, AML건 STR 연계)
```

### T2. 마목 확정 확인 — 대상: 확정 거래(BRK)

- **생성 트리거**: BRK-04에서 게시자 수락 → **즉시 확정(구속력 기발생)** → DSRV 확인 건으로 유입. T1과 달리 **거래 성립을 승인하는 게 아니라, 이미 확정된 거래의 이전(정산) 진행을 확인**하는 것.
- **생성 상태**: 정상 → `확인 대기` / 주의 이상(KYT 주의 등) → `에스컬레이션`

| 액션(사람) | 전이 | 후속 효과 |
|---|---|---|
| 승인 | 확인 대기 → 이전 진행 | BRK-05 정산 배치(1영업일 3회)로 진행 → 완료 시 종결 |
| 보류 | 확인 대기 → 보류 | 이전 개시 보류. 사유 필수, 양측에 일반화 사유 통지 |
| 거절(차단) | 확인 대기 → 이전 중지(종결) | AML 차단(예외 E3·F4) — STR 검토 연계. 확정은 기성립 상태라 **거래 취소가 아니라 이전 중지**. 이후 계약상 처리 [결정필요 ①] |

- 트래블룰 정보 불충족(예외 E7) 시: `보류` + 정보 보완 후 재진행.

### T3. 출금·이전 (서면 접수) — 대상: 출금·이전 요청

- **생성 트리거**: 서면 출금·이전 신청 접수(관리자 등록). 신규 주소면 화이트리스트 **지연발효 타이머 자동 시작**.
- **생성 상태**: `대기` (등급 표기: 지연발효 중 — 신규 주소 건)

| 트리거 | 전이 | 비고 |
|---|---|---|
| (시스템) 지연발효 만료 | 대기(지연발효 중) → 대기(승인 가능) | 타이머 전이 — 자동 승인 아님, 승인 버튼 활성화만 |
| 승인 (사람) | 대기 → 집행 대기 | T1과 동일 경로(서명·집행 → 완료). 지연발효 중에는 승인 불가 |
| 거절 (사람) | 대기 → 거절(종결) | 사유 필수 |
| (시스템) 출금 시점 BLF 재검증 적중 | 대기/집행 대기 → 차단(종결) | 예외 H3 — 차단 + STR 검토 아이템(T5 성격) 신규 생성 |

### T4. 입금 격리 — 대상: 입금 트랜잭션

- **생성 트리거**: 입금 자동 감시에서 KYT 고위험(예외 B1) 또는 BLF·제재 주소 적중(예외 B2) → **격리 지갑 자동 분리 + 잔고 미반영**과 동시에 아이템 생성.
- **생성 상태**: `격리 중` (등급: High). B2(제재 적중)는 생성 시점에 즉시 동결 상태로 유입.

| 액션(사람) | 전이 | 후속 효과 |
|---|---|---|
| 소명 요청 → 소명 인정 | 격리 중 → 해제(종결) | 격리 해제 · 잔고 정상 반영 · 고객 통지 |
| STR·동결 | 격리 중 → 동결(종결) | STR 검토 → 별도 AML 시스템 이관(작성↔보고 분리). B2는 §11② 통지·보고 절차 [원문대조필요] |

- 소명 요청~회신 대기 구간의 아이템 상태는 HOLD. 소명 시한 [결정필요 ②].

### T5. 이상거래 워닝 — 대상: 거래·게시 패턴 (자전·통정·위장게시)

- **생성 트리거**: 이상행위 룰 적중 — 연관 당사자 매칭(예외 D4) · 게시·취소 반복(예외 C5) · 사후 패턴 적발(예외 G2). 룰 적중은 자동, 판단은 사람.
- **생성 상태**: `미처리` (등급: 룰 심각도)

| 액션(사람) | 전이 | 후속 효과 |
|---|---|---|
| STR 검토 | 미처리 → STR 검토(종결·이관) | 별도 AML 시스템으로 이관 — 처리함에서는 이관으로 종결. 필요 시 해당 기관 `일시제한` 연계(T7 경로) |
| 무혐의 종결 | 미처리 → 무혐의(종결) | 판단 근거 기록 |

- 고객 화면에는 어떤 표기도 하지 않음(STR 누설 금지) — 처리 결과는 거래 상태로만 간접 반영.

### T6. 월렛·키 알람 — 대상: 지갑·키 이벤트

- **생성 트리거**: 콜드 워치 비인가 이체 시도 감지 · 핫월렛 비중 임계(20%, ADM-03) 초과 스윕 워닝(예외 B6) · 서명 시스템 장애(예외 F6).
- **생성 상태**: `미확인` (등급: High — 비인가 시도 / Mid — 스윕·운영)
- **전이**: `미확인 → 확인 → 조치완료(종결)` — 스키마 WALLET_ALARM(미확인/확인/조치)과 일치. 조치는 화면 밖 운영절차(키 교체·스윕·BCP), 처리함에는 결과만 기록.

### T7. KYC 재이행 — 대상: 기관·가입자 계정

- **생성 트리거**: 재이행 주기 도래(고1·중2·저3년) 후 **기한 초과·미응답**(예외 A6), 또는 이벤트 트리거 수시 재이행(실소유자·지배구조 변경, 예외 A4).
- **생성 상태**: `일시제한 예정` (등급: Mid)

| 트리거 | 전이 | 후속 효과 |
|---|---|---|
| 신규 거래 제한 (사람) | 일시제한 예정 → 제한 적용(종결) | 계정 상태 `활성 → 일시제한` (ADM-03 상태 기계 — 전 화면 게이팅 G-3 단일 출처) |
| (시스템) 재이행 완료 | 일시제한 예정 → 자동 종결 | 제한 적용 전 재이행이 완료되면 아이템 자동 종결 — **유일한 자동 종결 허용 케이스 (기획 가정)** [결정필요 ③] |

- 재이행 완료 후 `일시제한 → 활성` 복귀는 ADM-03 '상태 변경'(사람).

### T8. 계정 잠금 — 대상: 가입자 계정

- **생성 트리거**: AUTH-01 로그인 5회 실패 → 계정 자동 잠금과 동시에 아이템 생성. (계정 탈취 의심(예외 H5)도 동일 유입 — 등급 High·세션 차단 병행)
- **생성 상태**: `잠금`
- **전이**: `잠금 → 본인확인 후 해제(종결)` — 계정 상태 `잠금 → 활성` 복귀. 탈취 의심 판단 시 해제 대신 `동결` 전환(ADM-03 상태 기계) + T5 성격의 STR 검토 아이템 생성.

### (표 미노출 유입 2종)

- **제재·다크코인 적중**: 독립 유형이 아니라 T3(출금 시점 적중 = H3) 또는 T4(입금 적중 = B2)로 귀속 — 별도 행 불요 (기획 가정).
- **3면 대사 불일치(예외 X3)**: 대사 배치 불일치 감지 시 아이템 생성(`미처리`, High) + **해당 지갑 출금 자동 동결** 병행. 전이: 원인 규명 → 일치 확인·동결 해제(종결). 원인 규명 전 재개 금지. → 처리함 행 유형에 **추가 필요 (현 adm-02 표에 예시 행 없음)**.

## 3. 상태값 총목록 (enum 후보)

### 아이템 상태 (공통, 5종)

`OPEN(미처리)` · `ESCALATED(에스컬레이션)` · `IN_PROGRESS(처리중)` · `HOLD(보류)` · `RESOLVED(종결)`

- RESOLVED는 **결과 코드** 동반: 승인 / 거절 / 소명 인정 / 동결 / STR 이관 / 무혐의 / 조치완료 / 해제 / 제한 적용 / 자동 종결(T7)

### 도메인 상태 (화면 '상태' 컬럼 표출값)

| 유형 | 생성 시 | 중간 | 종결 |
|---|---|---|---|
| T1 나목 승인 | 승인 대기 / 에스컬레이션 | 보류 · 집행 대기 | 완료 · 거절 |
| T2 마목 확인 | 확인 대기 / 에스컬레이션 | 보류 · 이전 진행 | 완료 · 이전 중지 |
| T3 출금·이전 | 대기(지연발효 중) | 대기(승인 가능) · 집행 대기 | 완료 · 거절 · 차단 |
| T4 입금 격리 | 격리 중 | 소명 대기 | 해제 · 동결 |
| T5 이상거래 | 미처리 | 검토중 | STR 이관 · 무혐의 |
| T6 월렛·키 | 미확인 | 확인 | 조치완료 |
| T7 KYC 재이행 | 일시제한 예정 | — | 제한 적용 · 자동 종결 |
| T8 계정 잠금 | 잠금 | — | 해제 · 동결 전환 |
| (추가) 3면 대사 | 미처리 | 원인 규명 중 | 해제·종결 |

### 전이 주체 구분 (개발 구현 기준)

| 주체 | 허용 전이 |
|---|---|
| 시스템(자동) | 아이템 **생성** 전부 · 지연발효 만료(T3) · 온체인 확정 반영(T1·T3) · 재이행 완료 자동 종결(T7) · 격리/동결/잠금의 **개시**(T4·T8·X3) |
| 사람(관리자) | 승인 · 보류 · 거절 · 소명 인정 · STR 검토 · 무혐의 · 확인 · 조치완료 · 해제 · 제한 적용 — **종결성 판단 전부** |
